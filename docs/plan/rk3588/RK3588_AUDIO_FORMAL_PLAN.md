# RK3588 音频正式实现与验证方案

输入：`docs/issue/RK3588_AUDIO_FORMAL_ISSUES.md（A1～A8）`。
基准：当前工作树；ALSA 在板上可用，验证与实现条件已成熟。
修改原则：只改原模块，不新建替代模块；请求音频失败即 loud 失败，未请求走无声正常分支；控制面与数据面线程隔离不动。

## 阶段一：文件源重采样（对应 A1/A3）

目标：任意常见片源（采样率、声道数、采样格式）稳定产出会话约定的 PCM。

- 在文件源内引入 FFmpeg 重采样器，目标固定为会话约定的采样率与位深，声道数取发送会话的配置值。
- 解码器打开时读出片源实际采样率、声道布局与采样格式并初始化重采样器；已对齐时走直通，避免多余拷贝。
- 播放列表切文件时随新文件格式重建重采样器；旧上下文随解码器一并释放。
- 新增的声道数配置随文件源参数透传，非法值在创建时直接拒绝。
- 构建依赖增加重采样库，复用 sysroot 已有产物，不新增运行时依赖。
- 退出标准：非 48k/单声道/浮点片源仍能按会话帧长连续供帧，无错位；原 48k 立体声行为不变。
- 验证：板上用多格式片源跑文件源单发单收，断言音频供帧数与声道数匹配。

## 阶段二：请求即承诺，失败 loud（对应 A2/A3/A6/A8）

目标：音频故障不再被视频成功掩盖，三条链路口径一致。

- 发送侧直播链路：明确请求 ALSA 时，音频会话创建、声卡打开、协商值（采样率、声道数）三者任一不符即整栈创建失败；未请求时不触碰音频设备。
- 发送侧文件链路：音频会话创建失败即整栈失败；片源无音频轨属正常无声分支，仅音频线程不启动，视频照常。
- 接收侧单管线与合成器：仅当音频端口非零时打开声卡并建连，任一步失败即创建失败；音频端口为零时不打开声卡，直接无声同步。
- 采集侧 TX 后端：回读声卡实际协商值，非约定值即整路失败并给出原因，与直播链路一致。
- 涉及模块：发送主程序的文件与直播建栈、接收管线与合成器创建、采集编码后端音频启停。
- 退出标准：请求音频缺设备/协商不符时进程明确失败；未请求时日志无音频残留；单声道配置与协商不一致被拒绝。
- 验证：缺设备、错声道、零音频端口三组反例分别确认失败或无声符合预期。

## 阶段三：同步语义诚实化（对应 A4）

目标：文字与行为一致，死逻辑不再误导。

- 删除接收侧从未被调用的音视频判决分支，保留音频锚点记录、播出时刻计算与统计打印。
- 文档明确当前同步为固定延时播出策略，音频锚点仅做观测，不驱动视频丢帧或复帧。
- 若后续需要音频主钟驱动视频，另立项重做播出调度，不在本阶段复活旧分支。
- 涉及模块：接收同步模块头与实现。
- 退出标准：全仓无死分支引用；视频播出行为与改前一致。
- 验证：交叉编译通过，视频回归脚本结论不变。

## 阶段四：格式口径收敛（对应 A5/A6）

目标：硬编码收敛到一处约定，差异有文字说明。

- 发送与接收会话的采样格式、采样率、打包时长、负载类型保持现有约定不变，仅补齐创建时的参数校验与日志。
- 双音频发送实现（直播用的帧级会话与引擎用的管线会话）保留各自帧长，但统一失败语义与协商校验，差异在模块注释中说明。
- 涉及模块：音频发送封装、接收封装、播放封装注释。
- 退出标准：非法声道数在创建时被拒；正常路径日志可看出会话格式。
- 验证：参数反例单测与板上建连日志抽查。

## 阶段五：音频端到端断言（对应 A7）

目标：音频断流在脚本中即失败，不再只打印信息。

- 文件源单发单收用例升级为正式音频端到端：先探针片源是否含音频轨，含音频则断言发送侧音频供帧数大于零、接收侧音频帧数大于零且丢包为零、声卡无打开失败；无音频轨则断言发送侧明确无声并跳过接收音频断言。
- 直播回环脚本保持视频口径不变，音频覆盖归属文件源用例，避免 HDMI 音频采集不稳定污染结论。
- 单元层面保留现有声卡自测与仲裁字符串测试，不新增无硬件依赖的仿真断言。
- 涉及模块：多节点合成验证脚本的单路用例内嵌判定。
- 退出标准：含音频片源下音频三断言全过；无音频片源下明确跳过而非误过；声卡缺失时视频结论不受影响但音频项明确标注跳过原因。
- 验证：板上分别用含音频与无音频片源各跑一轮，确认通过与跳过行为符合预期。

## 里程碑与顺序

- 先落地阶段一与阶段二并同轮交叉编译一次通过，再做阶段三至五的脚本与清理改动。
- 任一阶段导致视频回归失败即停，优先查本阶段改动，不给等待加超时或降级分支。

# DVS Web 前端实现方案

## 1. 总体策略

- 保留原型页面结构与交互，仅替换数据源。
- 前端不持有业务真源，所有状态以后端为准。
- 前端不自行计算布局拆分，使用平台返回的像素坐标。
- 前端错误处理统一使用后端包络 `{ok,status,code,msg,data}`。

## 2. 平台前端改造

1. 替换 `mock-api.js` 为真实 fetch 封装，保持路径与响应包络。
2. 分组/拼墙/设置页面直接调用平台 REST API。
3. 画面调度页面：
   - 编辑态立即上屏（本地预览）。
   - 保存时提交场景快照。
   - 切换时调用 prepare/commit，显示目标节点状态。
   - 清屏调用 clear operation。
4. 设备列表页面：
   - 退役调用平台 retire。
   - 批量升级调用平台 upgrade。
5. 播放任务板：
   - 创建任务调用平台 API。
   - 状态流转由后端驱动，前端只展示。

## 3. 节点本机前端改造

1. 本机页直接调用节点代理 `/api/v1/node/*`。
2. 媒体状态/能力从代理接口获取，不再使用 localStorage。
3. 维护操作调用代理接口，显示进度与结果。
4. 网络配置失败时展示回滚提示。

## 4. 数据流

- 平台前端 → 平台服务 → 节点网关 → 节点代理 → 媒体引擎。
- 节点本机前端 → 节点代理 → 媒体引擎。
- 媒体状态通过心跳与 query_state 回流平台。

## 5. 验证

- 前端页面全部使用真实 API。
- 断网时前端展示离线状态，不崩溃。
- 同帧切换时前端显示节点 ready/blocked 状态。

# DVS 三引擎原型遗留 mock / 硬编码审计清单

审计范围：`app/dvs_agent`、`app/dvs_platform`、`app/dvs_media` 的生产代码（不含 `tests/` 下的测试替身）。
方法：关键词扫描（mock/stub/fake/prototype/todo/默认口令/固定路径）加逐模块精读，重点看认证门禁、能力与身份上报、网络/升级/重启执行语义、布局分发、媒体会话准入。
结论：三端均存在原型期为了联调跑通而留下的旁路与硬编码，部分已用注释自述为原型行为，未收敛前不可直接商用。

测试替身说明：`dvs_media/tests/test_tx_session.c` 的 `fake_backend_*` 与 `test_ipc.c` 的注释属于单测接缝，不在整改范围。`dvs_media` 正式二进制恒装 `live_ingest` 后端，`tx_session` 无后端分支仅 x86 单测使用。

## 一、dvs_agent（节点代理，C++）

### 1. 认证默认关闭，空令牌即放行

位置：`agent_auth.cpp` 认证门禁、`agent_context.h` 令牌字段、`main.cpp` 启动装配、`platform_context.h` 对应服务端。

现象：严格认证是可选项，环境变量未设置时所有接口直接放行；平台侧令牌为空时也不校验。注释自述为让原型前端免登录可用。

风险：局域网内任意进程可调用布局、配置、升级、重启接口，可伪造屏障回执。

整改：默认开启认证，缺令牌时拒绝启动或拒绝可变接口；浏览器会话与平台 Bearer 双通道保留，但不再允许双空；登录限流与会话过期保持。

### 2. 节点身份与能力种子为固定假值

位置：`node_store.cpp` 建库种子、`registration.cpp` 注册与心跳组包、`main.cpp` 地址回退。

现象：全新库预置固定身份与能力，例如固定节点名、固定序列号、零 MAC、回环地址、固定固件版本、固定解码与图层数、固定 TX  ceilings、PTP 与 MTL 标记为未知。注册时取不到真实值就用上述假值上报，心跳同理；无网络配置时用回环地址拼可达地址。

风险：平台看到的是假硬件画像，会据此做布局拆分与准入；零端口与假端口难以区分。

整改：种子只保留空骨架，缺失字段标记未知而非填假值；注册前做完整性检查，缺关键身份或能力时明确报错；能力以引擎探测为准，本地只做缓存不伪造。

### 3. 心跳资源字段 CPU 恒为零

位置：`registration.cpp` 心跳资源组包。

现象：内存从系统文件解析，温度读传感器文件，但 CPU 字段恒填零。

风险：平台容量调度与过载判断拿到假零负载。

整改：用两次采样差分计算真实 CPU，或在取不到时省略该字段并标记未知。

### 4. 容量探针为单次快照公式

位置：`agent_sys_routes.cpp` 容量接口。

现象：CPU 忙碌比用单次快照的总量减空闲除以总量得出，不是时间段内的增量比。

风险：数值不代表真实利用率，调试与容量评估会被误导。

整改：改为双采样差分，或复用与心跳一致的资源采集函数，避免两套算法。

### 5. 网络配置默认只落库不生效

位置：`agent_config_routes.cpp` 网络分支、`network_apply.cpp` 执行门与意图日志。

现象：不满足环境变量加确认加操作号三条件时，只写一条系统未动的日志并把落库标记为已应用，提示语区分意图已存与系统已切换，但状态机仍记为成功。

风险：调用方看到成功会误以为地址已切换，实际网卡未动；隔离环境联调语义泄漏到生产接口。

整改：拆分意图保存与系统生效两种终态，未执行时状态不得记为已应用；生产部署明确执行策略，测试注入失败开关不得编译进正式二进制。

### 6. 测试注入开关留在生产路径

位置：`network_apply.cpp` 与 `agent_config_routes.cpp` 的强制失败环境变量。

现象：特定环境变量可一键让网络应用失败，用于覆盖率测试。

风险：生产环境误设即大面积失败，且属于测试后门。

整改：移入测试构建或调试开关，正式构建不可用环境变量改变执行结果。

### 7. 重启与升级切换被环境变量门控，默认不执行

位置：`maintenance.cpp` 重启与升级、`agent_sys_routes.cpp` 上传接口。

现象：无对应环境变量时重启只返回延迟状态，升级只做暂存并报告已暂存；固件版本从文件名中找版本号，找不到则填固定升级标记；暂存与升级目录、上传目录均为固定路径；目录创建与重启经由 shell 命令。

风险：联调时以为升级成功实际未切换；固定路径无配额与清理；shell 调用与文件名拼接需严格校验。

整改：明确维护窗口与二次确认机制替代环境变量门；版本取自包元数据而非文件名；路径可配置并做大小与清理配额；危险操作走专用执行器而非 shell。

### 8. 固件上传接口缺少生产级防护

位置：`agent_sys_routes.cpp` 升级上传路由。

现象：上传文件名截断与长度检查后直接写入固定临时目录，大小无上限，失败只报无法写入。

风险：大文件打满磁盘，固定目录可被预测。

整改：加大小上限、分片校验、上传与升级事务关联、过期清理；认证收紧后仍需速率限制。

### 9. 底图拉取为固定临时路径加固定配额

位置：`media_ipc.cpp` 平台布局翻译中的底图处理。

现象：每版本底图缓存路径为固定模板，大小上限与拉取超时为固定值，无哈希校验，失败时仅打印日志并让引擎上报失败。

风险：临时目录堆积，多版本并发有覆盖风险；无完整性校验。

整改：路径纳入可配置缓存目录并做哈希校验与 LRU 清理；失败纳入屏障可观测状态而非仅日志。

### 10. 引擎通道数上限为源码硬编码镜像

位置：`media_ipc.cpp` 布局翻译的通道上限。

现象：上限值在注释中自述为镜像另一模块的常量，平台侧按更小值准入，此处仅为兜底。

风险：两处常量漂移会导致一边放行一边拒绝。

整改：由引擎能力接口或共享头提供唯一上限，代理不再复述数值。

### 11. 输出能力回退值与阈值三处重复

位置：`agent_config_routes.cpp` 输出校验、`agent_media.cpp` 热插拔重校验、引擎侧输出设置。

现象：无能力上报时回退到同一组固定宽高刷新率，窗口最小尺寸与模式白名单也在多处重复。

风险：任一处改动都会造成校验不一致。

整改：能力缺失时标记未知并拒绝输出变更，或由引擎能力快照提供唯一回退；阈值收敛到契约常量。

### 12. SIP 当前仅为连通性探测

位置：`agent_config_routes.cpp` SIP 分支、心跳 SIP 摘要。

现象：密码接收后不存储不上报，模式固定为连通性探测，状态只有探测中、已连通、不可达；判断依据为固定超时的 TCP 可达。

风险：会被误认为已实现 SIP 注册，对功放与平台联调产生错误预期。

整改：接口与文档明确标注探测模式；实现真正注册前不得上报已连通；密码字段在探测模式下应拒绝或明确忽略。

### 13. 输入未下发引擎仍记成功并带联调提示

位置：`agent_config_routes.cpp` 输入分支。

现象：无编码目标等价于仅保存采集口时直接记为已应用，但提示语带有数据面待联调字样；输出走后台线程异步等待引擎，输入走同步等待，两条路径不一致。

风险：联调提示语会出现在正式接口返回中；异步与同步的竞态处理不一致。

整改：区分已保存与引擎已接受两种状态；提示语不得包含联调阶段用语；输入输出统一为异步确认加状态机。

### 14. 本地单机垫片伪装平台网关

位置：`local_shim.cpp` 本地节点路由。

现象：在代理侧提供节点列表、心跳、升级、退役等伪平台接口，升级恒报成功，退役写固定符号。

风险：单机联调方便，但与真实平台行为不一致，容易掩盖网关缺失问题。

整改：明确标注仅单机调试使用，生产构建关闭；或收敛为只读诊断接口。

### 15. 热插拔与版本门禁节拍为固定值

位置：`agent_media.cpp` 热插拔轮询、能力过期、版本缓存。

现象：轮询间隔、能力过期阈值、版本握手缓存均为固定毫秒数；引擎失联初期返回在线未知等渐变状态。

风险：不同现场的 HID 与采集设备抖动需要不同节拍，固定值难以调优。

整改：节拍与阈值纳入配置，状态变化上报平台而非仅日志。

## 二、dvs_platform（平台服务，C++）

### 1. 空令牌即免检，与代理同源问题

位置：`platform_context.h` 令牌注释、`main.cpp` 启动警告、`node_routes.cpp` / `op_routes.cpp` / 升级路由的 Bearer 校验。

现象：令牌为空时注释明示为让本地原型可用，服务端仅打印警告仍继续服务。

风险：所有可变接口无认证，升级与布局可被任意调用。

整改：与代理同策略，生产缺令牌拒绝启动；测试用独立测试令牌。

### 2. 布局与资源预算多处硬编码且跨端重复

位置：`layout.cpp` 与 `layout_fanout.cpp`、`op_routes.cpp`。

现象：单节点窗口数、最小窗口边、墙行列范围、像素范围、默认帧率、提交保护间隔、PTP 偏移上限、分发并发、墙成员上限、组播地址池与默认端口等均为源码常量；默认端口与默认帧率在分发侧又重复一次。

风险：产品常量尚可接受，但跨代理与引擎重复的端口、帧率、分辨率上限会漂移。

整改：保留产品语义常量，但跨端常量收敛到契约；并发与上限纳入配置。

### 3. 前端方言容忍掩盖契约 violations

位置：`layout.cpp` 墙类型校验、`docs_routes.cpp` 回放任务别名归一、`upgrade_jobs.cpp` 文件字段别名、`op_routes.cpp` 墙与场景字段别名。

现象：为兼容原型前端与测试方言，接受多种字段拼写并自动归一，多节点任务才报错。

风险：脏数据被静默修正，契约测试失去意义。

整改：冻结期后收紧为严格校验，方言转换只保留在迁移脚本中。

### 4. 心跳回执版本号固定

位置：`node_routes.cpp` 心跳接口。

现象：心跳成功恒返回固定版本号，未反映真实应用版本。

风险：代理据此判断的配置收敛是假象。

整改：返回节点真实应用版本与待应用版本。

### 5. 注册缺关键信息仍入库

位置：`node_routes.cpp` 注册接口。

现象：无可达地址或无几何信息时仅记一条审计，仍写入节点文档。

风险：无几何节点会污染墙成员推导，后续分发再跳过，造成静默缺屏。

整改：缺关键字段直接拒绝注册，或标记为未就绪且不参与成员推导。

### 6. 白名单与文档标识用时间戳拼串

位置：`media_routes.cpp` 白名单分配、`docs_routes.cpp` 通用文档标识。

现象：无标识时用类型加秒级时间生成标识，白名单无信号时同样处理；地址池按固定网段顺序扫描。

风险：并发创建易碰撞，秒级标识可预测。

整改：改用随机唯一标识；地址分配加事务锁。

### 7. 回放任务单节点限制与别名逻辑耦合

位置：`docs_routes.cpp` 回放任务校验。

现象：归一逻辑先接受多种写法，再对多节点报 محدود限制。

风险：逻辑正确但归一层 prototype 色彩重，未来扩展多节点会被误改。

整改：契约固定单节点字段，移除别名后再做互斥校验。

### 8. 底图版本接口阈值硬编码

位置：`media_routes.cpp` 底图版本存取。

现象：版本号长度、宽高范围、地址长度等均为固定阈值，缓存键为字符串拼接。

风险：阈值与引擎解码上限各自为政。

整改：阈值引用引擎能力或契约常量；缓存键规范化。

### 9. 操作屏障默认与 GC 节拍硬编码

位置：`ops.cpp` 操作默认值、`ops_sweeper.cpp` 恢复与回收、`barrier.cpp` 屏障判定。

现象：默认音量、帧率、帧号、操作存活期、审计保留行数、墓碑与删墙保留期、扫仓间隔均为常量；提交时钟与帧一致性判定失败即整单阻塞。

风险：不同墙帧率与时钟条件需要可调，固定值会误伤。

整改：节拍与保留期纳入配置；阻塞原因结构化上报而非仅审计。

### 10. 无几何无通道节点静默跳过

位置：`layout_fanout.cpp` 分发、`op_routes.cpp` 缺失统计。

现象：分发时无几何或无通道即记跳过，调用方仅看到缺失名单。

风险：缺屏原因定位慢。

整改：缺失原因结构化返回，区分未注册、无几何、无通道、时钟不同步。

## 三、dvs_media（节点引擎，C）

### 1. 能力默认值为假画像

位置：`engine/capability.c` 默认填充与 JSON 序列化。

现象：解码数、图层数、TX 编码 ceilings、PTP 未知、MTL 后端标记、输出回退分辨率、输入端口上限等均为固定值；无 DRM 时输出零端口但仍上报固定解码能力。

风险：代理与平台会把默认值当真实能力做准入。

整改：探测不到即报未知或零并附原因；固定 ceilings 必须标注为 SoC 规格而非探测值，且与代理种子唯一来源。

### 2. 后端名映射为前缀硬编码

位置：`engine/capability.c` 后端判断与刷新。

现象：按固定端口前缀映射为内核或加速后端，双端口不一致即报未知。

风险：新增后端前缀需改多处。

整改：后端枚举由传输层提供，能力侧只透传。

### 3. 单调时钟下 PTP 恒未知导致平台门禁恒阻塞

位置：`engine/capability.c` PTP 刷新、`engine/ipc_engine_bridge.c` PTP 状态钩子。

现象：单调模式无 TAI 纪律时恒报未知，平台时钟门禁要求已同步，输入输出角色都会被挡。

风险：单调调试模式与平台门禁语义冲突。

整改：明确单调模式不得参与需要时钟对齐的墙，或为其定义独立的门禁策略。

### 4. 布局回退分辨率与帧率为固定值

位置：`engine/engine_ctx.c` 合成器构建。

现象：宽高非正时回退到固定分辨率，无帧率时按首流或固定值，DRM 模式按固定字符串。

风险：与代理校验的最小值不一致时会反复被拒。

整改：回退值引用能力探测结果，无能力时拒绝布局而非猜测。

### 5. 输出与 TX 范围三端重复

位置：`engine/engine_ctx.c` 输出设置、`engine/tx_session.h` TX 上限、`engine/tx_port_map.c` 默认帧率与 GOP、`app/dvs_agent/tx_config.h` 同名 ceilings。

现象：同一组宽高帧率码率上限在三处以不同形式出现；RX 白名单支持的编码多于 TX 支持的编码。

风险：改一处漏两处，联调时互相推诿。

整改：以能力上报为唯一运行时依据，编译期常量只保留绝对硬件红线；RX 与 TX 编码集合差异必须文档化。

### 6. 采集口命名与扫描范围硬编码

位置：`engine/tx_port_map.c` 表构建与设备扫描。

现象：采集口按固定前缀加序号命名，仅支持个位数序号；扫描固定设备号区间；稳定标识用固定分隔符拼接；无信号判断用固定小分辨率阈值，注释自述为占位检查。

风险：多路采集盒与异形驱动会被截断或误判无信号。

整改：端口命名与扫描区间可配置；信号检测用真实制式锁定状态替代分辨率占位。

### 7. 准备延迟为固定模拟休眠

位置：`ipc/ipc_server.c` 异步准备工作线程。

现象：每次准备固定休眠一段毫秒数，注释自述为模拟首帧等待，实际 lane 统计已接入但就绪语义仍为模拟。

风险：屏障等待时间被人为拉长，失败归因失真。

整改：以真实首帧或会话就绪事件替代固定休眠；保留超时但不得用休眠伪装工作。

### 8. 并发与超时上限硬编码

位置：`ipc/ipc_server.c` 执行器与连接表。

现象：重 verb 串行单槽、忙时直接报忙、等待超时固定值、最大客户端与幂等缓存环均为常量；IPC 文件权限与同用户检查为固定策略。

风险：多代理通道并发会被误报忙；容器多用户场景被拒。

整改：并发与超时纳入配置；权限模型文档化并支持组模式。

### 9. 音频设备与混音器硬编码

位置：`engine/audio_arbiter.c` 音量应用。

现象：无配置时用默认设备名，混音元素固定为主音量，音量为线性映射。

风险：无主音量元素的声卡直接静默失败，音量曲线不符合听感。

整改：设备与元素名可配置，缺元素时明确上报而非静默；必要时引入等响曲线。

### 10. 底图仅软解且拉伸算法固定

位置：`engine/base_image.c` 解码与画布适配。

现象：仅支持若干像素格式的软解，画布上限固定，最近邻拉伸，裁剪越界才报错。

风险：大底图软解耗时，画质不符合 LED 墙要求。

整改：优先硬件缩放，算法与上限可配置，失败原因结构化。

### 11. 无数据面后端时报配置成功

位置：`engine/tx_session.c` 无后端分支、`engine/ipc_engine_bridge.c` TX 启动钩子。

现象：无后端时参数校验通过即返回成功并标记后端待定，调用方看到成功但无流。

风险：测试接缝语义泄漏到正式接口，与代理的待联调提示形成闭环假象。

整改：正式二进制缺后端视为启动失败；测试接缝用构建开关隔离。

### 12. 空布局与清理路径帧锚固定

位置：`engine/layout_executor.c` 清理与提交、`engine/engine_ctx.c` 空合成器重建。

现象：清屏重建零通道合成器并用固定帧率与帧号，MTL 常驻以加速下次提交。

风险：语义正确但固定帧锚会污染提交报告。

整改：清屏报告区分空布局与帧锚提交，避免 barrier 误读帧号。

## 四、整改顺序建议

先收敛认证与身份假值，再收敛能力与预算重复，最后收敛执行语义与固定节拍。认证与假能力直接决定平台调度的正确性；能力重复决定多端是否同口径；执行语义决定联调结论是否可信。固定节拍与路径可在联调稳定后逐步配置化。

复查方法：整改后重新执行本清单的关键词扫描，确认注释中不再出现原型免登录、系统未动、连通性探测、模拟等待、占位检查、待单板联调等表述；跨端常量只保留一份来源，其余引用。

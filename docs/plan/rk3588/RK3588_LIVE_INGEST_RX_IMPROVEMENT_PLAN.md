# RK3588 Live Ingest 接收/解码链路改进设计方案

对照基线：TX 链路已落地的模式（代际归还、HangGuard 看门狗、防风暴重建、1s 聚合日志、DMA32 堆、VUI 注入）。
被改进对象：`app/rk3588_live_tx/`（`mtl_rx.c`、`mtl_rx_bridge.c`、`pipeline/rx_pipeline.c`、`pipeline/slice_reassembler.c`、`codec/mpp_decoder.c`、`io/drm_renderer.c`）。

## 1. 现状对照总结

| 维度 | 接收链路现状 | 目标做法 | 差距等级 |
|---|---|---|---|
| MTL 帧缓冲归还 | lcore 回调内 ring 满即归还 fb，不阻塞，正确；但只有 drops 计数 | 在途/峰值/满事件计数 + 5s 限频告警，与 TX 采集侧口径对齐 | 中 |
| 网损 vs 解码挂死 | 无区分、无看门狗、无重建 | 监督逻辑区分无输入与有输入无输出，挂死重建解码器，超限禁用 | 高 |
| 桥接拷贝 | slab 分配 + 全帧 memcpy 后立即归还 MTL fb，正确；SEI 用 extract 做全帧 memmove | SEI 改 peek 加偏移直送解码器，省一次全帧搬运 | 中 |
| 解码器输入语义 | put 后立即释放输入缓冲，隐含假设 MPP 同步拷贝输入 | 确认 MPP 是拷贝还是引用；若为引用则保持到有输出后再释放 | 高（潜在 UAF） |
| 解码忙等 | `decode_get_frame` 超时后 50µs 自旋 ×30 | 改为与 TX collector 一致的微秒级让出等待 | 高 |
| 解码输入满 | 内部 drain 一帧但不显示不计数，静默丢失 | 记为 drop 并上报，不静默 | 中 |
| 分辨率变化 | info-change 只建缓冲组，不更新尺寸、不通知渲染器 | 分辨率变化回调重建渲染器，与 TX 信号重建对等 | 高 |
| 切片重组 | 有上一帧才吐上一帧，引入 1 帧延迟；尾帧在停止时丢失；每帧 malloc | 帧级传输默认旁路保持；多切片时加超时刷新与停止 flush，改 slab 分配 | 中 |
| DRM 句柄 | 每帧 PrimeFDToHandle 后从未关闭 GEM 句柄，长稳泄漏 | ADDFB2 后立即关闭 GEM 句柄 | 高（泄漏） |
| 显示错误恢复 | 显示失败只返回错误码，调用方丢弃，无重建 | 显示失败触发渲染器重建，与 TX 重建纪律对等 | 中 |
| 时钟域 | SEI 时间与本地时间直接相减，无合法性检查 | 差值异常（负值或超 1s）不计入并单独计数 | 中 |
| 帧序号 | SEI 序号解析后丢弃，无丢帧定位 |序号 gap 计数，区分网损丢帧与解码丢帧 | 中 |
| 可观测性 | 只有停止时一条汇总，无运行期日志 | 与 TX 对齐的 1s 聚合日志 | 中 |
| 错误传播 | 解码渲染返回值被调用方丢弃 | 接入监督触发器 | 中 |

## 2. 改进方案

### 2.1 MTL 接收层（mtl_rx.c）

归还策略保持不变（ring 满即归还，不阻塞 lcore，这是 live 正确的背压语义）。
补齐与 TX 采集侧同口径的观测：在途描述符数、峰值、池满事件，池满打 5s 冷却
告警。接收 pps 与丢弃 pps 进入 1s 聚合。停止路径的双重 drain 保留（幂等、无害），
不做结构调整。

### 2.2 桥接层（mtl_rx_bridge.c）

拷贝后立即归还 MTL fb 的纪律保留。SEI 处理从原地剔除改为只读探测加偏移直送，
解码器从载荷偏移处开始读取，slab 块仍按基址归还，消除每帧一次全帧搬运。
输入缓冲的生命周期以 MPP 的真实语义为准：先确认解码 put 是同步拷贝还是异步
引用，若为引用则把释放点推迟到对应输出产出之后。桥接的 slab 分配失败只可能
发生在停机注水期，保持直接丢弃计数。补 bytes 统计，供码率推算。

### 2.3 解码层（mpp_decoder.c）

超时等待从自旋改为让出等待，与 TX collector 的空闲策略一致，避免在高切片数
下单帧内多次自旋叠加超过帧周期。输入队列满时的内部 drain 明确记为一次解码
丢弃，不再静默。info-change 在重建缓冲组的同时上报新分辨率，由编排层决定
是否重建渲染器。解码耗时加 EMA 统计。长期无人调用的直送入口确认后删除，
不保留死代码。

### 2.4 切片重组（slice_reassembler.c）

帧级传输是当前 MTL 会话的实际形态，每个 MTL 帧即完整图像，重组器默认旁路的
现状保持不变。多切片模式下补齐三处：无后续帧时按超时吐出已缓存帧，避免固定
1 帧延迟；停止时 flush 尾帧；缓存改 slab 分配消除每帧堆分配。自测宏接入
meson 使其在 x86 可编译运行，与 sps_vui 单测对等。

### 2.5 显示层（drm_renderer.c）

每帧导入的 GEM 句柄在 ADDFB2 成功后立即关闭，ADDFB2 持有自身引用，关闭不影
响显示，消除每帧一个句柄的长稳泄漏。显示失败（flip/setcrtc 连续失败）向上传
递为可重建错误，由编排层重建渲染器。连接器匹配与模式选择维持现状（板上可用），
热插拔检测暂不引入，超出本阶段范围。

### 2.6 编排与观测层（rx_pipeline.c、live_ingest_app.c）

新增与 TX 对等的监督线程：跟踪已接收与已渲染计数及最近输出时刻，区分三种
状态——无输入为网损或信号中断、有输入无输出超时为解码挂死、输出正常为健康。
挂死走解码器加渲染器重建，连续触发超限则粘滞禁用并告警。解码与显示的返回值
全部接入触发器，不再丢弃。

日志与 TX 对齐为 1s 聚合：接收、解码、渲染速率，丢弃分类计数，序号 gap 计数，
缺时间戳计数，延迟按秒重置窗口并保留累计极值，桥接与 MTL 侧水位一并输出。
延迟合法性先行检查，时钟域错配或跳变不计入统计。停止时的汇总日志保留。

### 2.7 明确不引入的部分

以下机制与本链路场景不匹配，暂不采纳：
- **音频与唇同步**：本链路纯视频直显，mp4_dist 的 AV 同步框架不适用。
- **OSD 与多窗口合成**：file_playout 的 compositor 面向文件分发，与 live 低
  延迟直显目标冲突。
- **暂停与按需启停**：ST 2110 接收持续运行，无读者事件概念，同 TX 结论。
- **接收端码率自适应**：码率控制是发送端 RC 职责，接收端只做解码显示。

## 3. 实施顺序

| 阶段 | 内容 | 依赖 |
|---|---|---|
| 1 | 显示 GEM 句柄关闭（泄漏修复） | 无 |
| 2 | SEI 只读探测加偏移、序号 gap 计数、延迟合法性检查 | 无 |
| 3 | 解码等待改让出、输入满记丢弃 | 无 |
| 4 | 1s 聚合日志与缺时间戳统计 | 依赖阶段 2 的计数 |
| 5 | 接收监督线程与解码渲染重建 | 依赖阶段 3、4 |
| 6 | 分辨率变化与显示失败重建 | 依赖阶段 5 |
| 7 | 切片重组超时刷新、停止 flush、自测接入 | 无，可并行 |

阶段 1 单独最高优；2–4 相互独立可并行；5 是最大结构改动；6–7 增量叠加。

## 4. 验证方式

- 纯逻辑模块（序号 gap 计数、SEI 偏移、重组 flush）进
  `app/rk3588_live_tx/tests/`，参照既有单测风格，可 x86 运行。
- GEM 句柄修复用长稳前后句柄计数对比验证，不等修复后增长。
- 板上 24h 长稳观察 1s 日志：丢帧率有界，延迟窗口稳定，无挂死误报。
- 断网、无信号、分辨率切换演练：网损与解码挂死告警可区分，恢复后自愈。

# 合成器渲染速率低于主路帧率（约 39fps 对 60fps 内容）【观察项，非失败】

日期：2026-11-09，修订：2026-11-09（分析修正 + P0 落码）。
板上实测（T2 双路合成，主路 HDMI 1080p60，次路文件 1080p24，1080p60 显示模式）。

## 1. 现象

- 双 lane 解码产出均约 99.9%（lane15000：2387/2388；lane15010：961/962），
  零丢包零坏帧，DRM 提交零错误，两窗口同时出画成立。
- 但合成计数稳态约 388/10 秒（约 39fps），低于主路 60fps 内容帧率。
  TX 停止后合成计数归零（无新帧即 idle，符合预期）。
- 单路验证既有相同性质的结论：呈现数约为解码数的八成，
  差额为按时钟渲染策略的主动跳帧，属预期行为。

## 2. 根因分析（修正原版两处偏差）

- 时钟策略与提交成本是两回事，不可混为一谈。
  渲染线程按主路时钟取到期最新帧，解码快于显示即丢弃中间帧，
  这部分差额是 newest-drop 主动跳帧，不是丢包也不是提交慢。
  原版把跳帧与提交慢混在一起，导致 39fps 既被解释为主动行为，
  又被解释为被动瓶颈，无法指导优化。
- 原版对提交路径的描述有事实错误。
  背景 SetCrtc 并非每轮一次：显示后端以标志位守卫，
  首帧提交后稳态不再做模式设置，稳态每轮成本只是
  每层一次导入加一次平面提交（本轮为两次导入加两次提交）。
  以 38–39fps 反推每轮约 25ms 的算法不成立，
  因为该反推把时钟等待与跳帧等待也算进了提交耗时。
  在补齐分段耗时统计前，任何“主要花在内核调用”的结论都属推测。
- 本轮还发现两处与吞吐直接相关的正确性问题。
  其一是导入句柄泄漏：每次导入新建的图形句柄从未关闭，
  随合成次数单调增长，既拖慢后续导入也终将耗尽句柄表。
  其二是无屏障显示的零成功被记为成功：全部图层提交失败时
  仍返回成功，调用侧会计入一次合成，污染 39fps 这个基线数字。
  另有 backdrop-only 路径从未真正点亮背景，属于同次排查的附带缺陷。
- 未排除项仍多：图层数放大的理论成本是线性增长，
  但 2 lane 数据不能外推 4 lane；CPU 亲和冲突、解码持有
  与显示帧缓冲的生命周期竞态、缺少垂直同步导致的撕裂与
  节奏抖动，都可能是 25ms 表象的一部分，需基线数据逐一排除。

## 3. 修改方向（按序推进，P0 本轮已落码）

- P0 正确性与基线（已实施，不待实测）。
  关闭导入句柄泄漏，成功与失败路径均关闭临时句柄，
  帧缓冲的内核引用仍由帧缓冲对象本身持有。
  显示后端零图层提交成功时返回错误，不再计入合成。
  背景独显路径改为专用背景提交接口，解决独显黑屏不显示问题。
  合成器新增渲染耗时基线：每次合成记录显示提交耗时，
  累计平均、最大值与慢轮计数，并区分主路跳帧与次路跳帧，
  定期报告同时给出时段增量与累计值，用于区分主动跳帧与被动拖慢。
- P1 帧缓冲复用（待基线达标后再决策）。
  若基线证明导入占主导，再按文件描述符加步幅建缓存，
  命中则跳过导入与分配销毁；命中率与 stride 变化处理是验收重点。
  基线不足以证明导入主导时不启动，避免引入陈旧帧缓冲风险。
- P2 平面提交合并（待 P1 之后，属架构级）。
  调研原子提交单次合并多平面并对齐垂直同步，
  需先确认驱动原子能力并保留传统逐平面提交回退。
  该方向同时解决撕裂问题，4 lane 时收益才显著，
  2 lane 基线未达标前不启动。
- 原版方向一（背景只提交一次）经核查已实现，不再列为优化项，
  后续只保留回归约束：稳态合成不得触发模式设置。

## 4. 验证（本轮证据 + 新增基线字段）

- 稳态合成计数单调增长且与主路时钟同节奏（每 10 秒约 388），
  不是停滞或抖动。
- `drm_smoke` 同板确认 4 个 NV12 overlay plane 可用且 SetPlane 缩放正常，
  显示能力基线存在。
- 新增基线字段验收：定期报告需含时段合成增量、时段渲染平均耗时、
  渲染最大值、慢轮计数、主路与次路跳帧增量、各 lane 播放缓冲溢出数。
  只有同时看到渲染平均耗时与跳帧增量，才能判定下一轮是否进入 P1。
- 本轮判定仍只要求合成输出大于零且零错误，不设渲染帧率门限；
  但同一份日志必须能回答慢是提交慢还是跳帧多，否则视为基线缺失。

## 5. 遗留（下一轮门限明确化）

- 4 lane 满配渲染速率未测：合成器直显上限 4 路，本轮只验证 2 路。
  满配轮次需记录合成速率、渲染平均与最大值、慢轮占比、
  跳帧增量与整机负载，作为能力上限证据。成本按图层数线性增长
  是理论预期，实际数值以实测为准，本轮不预判快慢。
- 人眼复检仍欠：日志只能证明提交成功。需站屏确认
  主画面全屏内容正确、右下 PiP 内容持续变化、无撕裂。
  若 P2 原子提交上线，复检需增加跨图层同步性确认。
- 下一轮功能门限建议：2 lane 合成帧率不低于主路帧率九成五，
  且慢轮占比收敛；未达标则按 P1、P2 顺序继续，不跳步。

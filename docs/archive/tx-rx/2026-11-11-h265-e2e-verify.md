验证对象：`3db85359 add h265 support`、`9a99e987 update h265 support 2`
及后续编译修复（dvs_media 单测补 `mtl_dep`；dvs_platform 换 `list` 队列 +

原始日志与详细记录见 `docs/archive/perf/2026-11-11-h265-e2e-verify.*`。

## 1 前置环境（每次重启后必做）

```bash
ssh board "sysctl -w vm.nr_hugepages=1024"   # 易失，重启丢失；缺它 MTL EAL 起不来
ssh board "cd ~/code/mtl/bin && ./board_env.sh status display,capture,net"
```

- `MtlManager` 需运行（`board_env.sh run` 会自动起）。
- 板 `bin/run_tx_rx_e2e.sh` 必须是 H.265 版（含 `CODEC` 透传）：
  `grep -c CODEC ~/code/mtl/bin/run_tx_rx_e2e.sh` 非零。
  若为旧版，按 `docs/dev/board-mtl-sync.md` 从仓库
  `app/rk3588_playout_rx/tests/` 同步新脚本到板 `src/playout-tests/`，
  再 `cp` 到 `bin/`（两处 md5 须一致）。

## 2 H.265 e2e（一键）

```bash
ssh board "cd ~/code/mtl/bin && export CODEC=h265 \
  RX_LOG=/root/code/mtl/perf/verify-YYYYMMDD/tx_rx_h265_rx.log \
  TX_LOG=/root/code/mtl/perf/verify-YYYYMMDD/tx_rx_h265_tx.log && \
  ./board_env.sh run -- ./run_tx_rx_e2e.sh 30"
```

`board_env.sh run` 自动完成 prepare（停桌面释 DRM/声卡）→ 跑 → restore
（恢复桌面）。SEC=30 约 1 分钟；判定内置，`OVERALL: PASS` 即过。

## 3 本次结果（2026-11-11，SEC=30）OVERALL: PASS

- TX：`mpp_enc: h265 1920x1080 gop=60 40000000bps`；
  `1795 captured, 1794 encoded`（99.94%），`ring_drop=0 sink_drop=0`
- RX：`mpp_dec: h265 1920x1080 pool=32 split_parse=1`；
  `1622 pkt, 1621 dec`（dec/pkt=99.9%），`pb_push=1621 render=1613`，
  `pb_skip=1 pb_overrun=0`，`0 put_fail, 0 prep_bad`，
  `underrun 376->376`（稳态收敛，初填后不再增长）
- 判定：收流等速 / 零丢包 / 零坏帧 / 解码无反压 / 发送跟上帧率，全 PASS；
  `render/dec=99.5%` 为 latest 帧策略跳帧，属预期
- 附带：H.264 对照跑一次亦 PASS（旧脚本未透传 CODEC 时的误跑，
  证明重编二进制链路正常）

## 5 踩坑记录（后续必读）

1. **CODEC 透传是静默的**：旧版 `run_tx_rx_e2e.sh` 忽略 `CODEC`，
   会静默跑成 h264 照样 PASS。判定前务必 `grep mpp_enc/mpp_dec` 确认编解码器。
2. **hugepages 重启丢失**：`HugePages_Total=0` 时 RX 报
   `EAL: Cannot get hugepage information`。先设再跑。
3. **D 状态 Xorg 占 DRM master**：`fuser` 显示占用 + `/proc/<pid>/status`
   为 `D` + wchan `misc_open` 即 wedge，`kill -9` 无效，
   `file_playout_rx` 无显示必 abort（`renderer create failed`）。
   **禁止自行 reboot**（关机易被 D 进程拖住致 SSH 长期失联），报用户手动处理。
   健康态 Xorg 为 `Ssl`，`board_env.sh run` 的停/启桌面在其上工作正常。
4. **`lightdm stop` 可能是 wedge 触发路径**：本轮 wedge 均出现在 stop/restart
   桌面之后；`board_env.sh run` 一次通过即收，不要反复 prepare。
5. **网卡 IP 收敛有时滞**：重启后 `enP2p33s0` 地址可能晚到，
   preflight 报"无 IPv4"时稍后重试 `status net` 即可。

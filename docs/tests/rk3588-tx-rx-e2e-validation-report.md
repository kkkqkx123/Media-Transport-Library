# RK3588 TX/RX 单板正式验证报告

日期：2026-11-09。设计依据见同目录 `rk3588-tx-rx-e2e-verification-design.md`。
脚本见 `app/rk3588_playout_rx/tests/run_tx_rx_e2e.sh`，板端同路径已部署到
`~/code/mtl/bin/run_tx_rx_e2e.sh`，本轮即以该脚本执行。

## 1 环境

开发板单板，系统为 5.10 内核。HDMI 输入信号锁定 1920x1080 60.01fps，
采集格式为 BGR3；HDMI 输出接显示屏，显示模式为 1920x1080p60，已点亮。
可用网卡为 enP2p33s0，地址为 192.168.80.202；其余网卡无载波或 PHY 异常，
本次不使用。MtlManager 已清理僵尸进程后重起为正常守护，大页 1024。
两二进制与仓库交叉编译产物哈希一致，无需重新部署。

## 2 拓扑与参数

单板回环，收发同机经物理网卡地址互通，不经过外部交换机。
接收先起，3 秒后再起发送，时长 60 秒。视频为 1920x1080 60fps，
视频端口 15000， pacing 为窄间隔形态，时钟为相对锚定。
相对锚定下端到端绝对值不测量，只验证节奏与等速，这是预期行为。

## 3 结果

正式轮一次通过。发送侧采集 3595 帧、编码 3586 帧，跟上率 99.7%，
编码耗时均值约 4.3 毫秒，分位上界约 5 毫秒，无环形队列丢帧。
接收侧收包 3406、解码 3405，解码产出比 100%，零丢包零坏帧，
解码器无反压。解码耗时中位约 3.4 毫秒，分位上界约 13 到 17 毫秒。
呈现 2806 帧，约为解码数的八成，差额为按时钟渲染策略的主动跳帧，
属预期行为。缓冲欠载在启动排空后收敛，稳态不再增长。
显示提交全程成功，无 DRM 错误。

此前另做两轮对照：回环经本机地址与经物理网卡地址结论一致；
发送打开 TAI 时间戳加接收切外部时钟的一轮视频等速同样正常，
但端到端均值约为 37 秒，恰等于内核 TAI 偏移量。
根因为接收外部模式取时钟源为 TAI，而发送默认取时钟源为实时钟，
两域相减多出闰秒偏移。该问题只影响绝对时延读数，不影响视频等速、
解码、呈现结论，已记为后续统一时钟域事项。

## 4 人工确认事项

日志只能证明提交成功，不能证明人眼所见。需在显示器旁确认三项：
画面连续无黑屏花屏撕裂；画面内容随输入变化；
发送码率变化方向与画面复杂度变化方向一致。
以上由人工在本轮或复跑时目视确认。

## 5 后续

## 6 追补：BGR 直投编码分块故障（已修复）

计数全绿后人工看屏发现链路显示为横向 3 分块加条纹。
照片经列自相关确认为精确 640 周期；网流离线重解同样 640 周期，
而直通显示与离线探针输入均为干净单场景，遂锁定故障在网流字节本身。
隔离实验证实：干净 BGR3 经 MPP BGR888 直投编码即出 3 分块，
与 zlmediakit 对照一致——其编码器只收 RGA 转好的 NV12，从不直喂 BGR。
修复为 BGR 改走 RGA 转 NV12 后编码（`tx_encode.c` 去掉 BGR 直投分支，
`mpp_encoder.c` 收敛为纯 NV12），`rga ok` 从 0 变为 60/s，
网流离线重解恢复干净单场景。看屏确认待人工复检。

# MTL 应用层使用情况与整改方案

整理日期：2026-11-04
范围：`app/rk3588_live_tx`、`app/rk3588_playout_rx`、`app/dvs_media`、`app/dvs_agent`、`app/dvs_platform`

本文先概述三类应用如何使用 MTL，再列出已确认的问题与分阶段整改方案。
长篇设计论证见既有 `docs/plan` 下各专项计划，本文只收敛与本次改动直接相关的结论。

## 1. 使用方式概述

三类应用都只使用 MTL 会话层，不触碰传输层内部。

共性：每个进程持有一个 `mtl_init/start` 实例；视频用 `st22` 帧级码流会话，
音频用 `st30` 帧级会话；发送侧采用直接写帧缓冲加生产者发布的手法，
接收侧采用接收回调只做入队加桥接线程拷贝的手法，以保证 MTL 调度线程不阻塞。

live_ingest 是单会话低延时链路。发送与接收各为独立进程，发送链为采集编码后
直接发布到单个 `st22` 发送会话，接收链为单个 `st22` 接收会话经桥接送解码显示。
端口类型写死，发送与接收队列各取其一。

file_playout 是多路分发链路。发送端每个视频流对应一个 `st22` 发送会话，
主路另带一个 `st30` 音频发送会话；接收端每个画中画分路对应一个 `st22` 接收会话，
另带一个 `st30` 音频接收会话加合成显示。初始化函数按端口名前缀选择后端类型，
支持外部时间源与单队列共享收发，发送侧可选用户时间戳 pacing。

dvs_media 是 file_playout 接收侧的演进，只收不发。单个 MTL 实例常驻，
当前布局对应一个多路合成器，布局变更时重建合成器。控制面拆分清晰：
媒体逻辑在 dvs_media，节点管理在 dvs_agent，跨节点编排在 dvs_platform，
后两者不直接调用 MTL，只经进程间接口下发布局。

## 2. 问题清单

错误地址静默通过。六处会话创建以宽松方式解析点分十进制地址，
解析失败时保持全零地址继续创建会话，错误配置会被掩盖为收不到流。
越界分量经窄化后也会被截断，同样掩盖问题。

live_ingest 后端写死。端口类型固定为原生 AF_XDP，不支持按端口名前缀选择
内核套接字等后端；在当前网卡不支持 XDP 时只能失败，无法回退到可用后端。
同时缺少单队列共享收发标记，与 file_playout 已修复的音频视频共存问题同类。

队列数强制填一。初始化函数把传入的零队列数改写为一。
接收专用实例因此多占一对发送队列，浪费本就紧张的单队列网卡资源。
底层已能处理零值并保证至少一对队列，强制填一没有必要。

注释与契约过时。部分头文件注释引用外部设计文档章节编号，
部分注释称接收丢包统计尚未接通，与合成器已提供按路丢包与时间戳查询的现状不符。
会话管理模块注释把逐路会话管理描述为未来事项，实际当前语义就是组合生命周期入口，
表述容易误导。

大结构问题本次不动。合成器全量重建而非逐路增删、live_ingest 双进程模型、
多应用重复的收发封装与显示解码副本，均需编译服务器与板端验证配合，
列入后续阶段，不在本次改动范围。

## 3. 整改方案

本次实施的三项小改动均只改原模块，不新增替代模块。

第一，收紧地址解析。发送会话要求目的地址必须存在且每段在合理范围内，
否则直接创建失败；接收会话允许源地址为空表示接收任意源，
非空但非法则同样创建失败。不再以全零地址继续运行。

第二，补齐 live_ingest 初始化语义。按端口名前缀选择后端类型，
与 file_playout 保持一致；单队列时置共享收发标记，保证后续扩展音频或多会话时
不重蹈单队列复写问题。保持原有队列数语义与绑定标记不变。

第三，透传队列数并清理注释。初始化函数不再把零改写为一，
调用方传零即表示该方向无专用队列，由底层按最小一对队列兜底。
共享标记判定改用实际生效的队列数。同时删除头文件中的外部文档章节引用，
更新接收统计与会话管理注释使其与现有实现一致。

后续阶段需在编译服务器上完成。逐路增删会话替代全量重建、
收发封装与显示解码副本收敛到公共位置、live_ingest 双进程合一、
板端回环收帧与长稳验证，均依赖交叉编译与硬件环境，不在本地执行。

## 4. 验证说明

本地只验证与 MTL 无关的控制面与纯逻辑部分。
本次六处地址解析改动与初始化改动属于 MTL 强相关，
按仓库编译规范不得在当前机器编译，必须同步到编译服务器后按既有流程验证。
建议验证顺序为先跑发送接收最小用例确认非法地址直接失败，
再跑单队列内核后端确认收发正常，最后跑多路合成确认共享标记生效。

## 5. 验证结果（devs 编译服务器）

使用 `arm-gnu-toolchain-13.3` 与既有 `build-aarch64` 目录，三应用均编译链接成功：
`rk3588_live_tx/live_ingest`、`rk3588_playout_rx/file_playout_tx`、
`rk3588_playout_rx/file_playout_rx`、`dvs_media/dvs_media`。
`test_pipeline` 也通过补充 `mtl_rx.c`/`mtl_rx_bridge.c` 源文件完成链接。

## 2. REQ-2026-0001 分组管理

纯控制面。建议直接使用 `dvs_group` 表，唯一约束为 `lower(trim(name))`。

实现要点：

- 删除前统计 `dvs_wall` 中未软删除的墙数量，非零返回 `RESOURCE_IN_USE` 并带 `wallCount`。
- 拼墙删除或移动到其它分组后，分组计数实时归零，随后允许删除。
- 不设数量上限，列表分页。

MTL 不参与。

## 3. REQ-2026-0002 拼墙管理

控制面为主，新增墙时生成一个默认场景。

实现要点：

- 行列上限 1–6 / 1–15；LED 模式隐藏类型字段，逐行逐列像素 64–7680。
- 新建时计算整墙像素坐标系 `wallPixelWidth`、`wallPixelHeight`，作为后续窗口与绑定的公共坐标基准。
- 删除前置：无窗口、无绑定、无进行中 operation、无播放中任务；通过后墙和场景进入 7 天软删除。
- 恢复墙时不自动恢复绑定，需要重新绑定。

MTL 不参与，但墙的像素坐标系是媒体面布局的输入，必须在建墙时固化并带 revision。

## 4. REQ-2026-0003 拼墙设置

### 4.1 MTL 相关部分

| 设置项 | 实现 |
| --- | --- |
| 传输白名单 | 每个输入盒分配一个组播地址和端口，写入 `dvs_whitelist`；节点代理下发到媒体引擎 |
| 传输方式 | 组播为默认；单播用于不支持组播的网络或调试 |
| 图像调节 | DRM plane 属性、RGA 或 GPU 着色器；需要逐项验证 RK3588 支持度 |
| 高清底图 | 平台把整墙底图按格位拆分为每节点子图；节点作为最底层 plane 或预合成背景 |
| 基本设置 | 名称、分组、色彩格式、视频质量、缓冲、时间服务器、同步时钟 |

### 4.2 组播地址分配

建议平台维护地址池，例如 `239.10.<wallIndex>.<sourceIndex>`，端口按输入源递增。分配规则：

1. 每个输入盒的每个采集口一个组播组。
2. 同一输入源被多面墙引用时复用同一组播组，避免重复编码。
3. 白名单只决定哪些墙可以订阅，不改变组播地址。
4. 地址冲突在保存时校验。

### 4.3 底图拆分

底图是拼墙级静态图，按整墙铺满。平台按每个节点的格位并集裁剪出子图，节点把子图作为最底层显示。窗口覆盖在底图之上，清屏后只剩底图。

实现路径：

- 平台存储原图，按节点生成子图缓存。
- 节点启动或收到设置变更时拉取子图，解码为 DRM framebuffer。
- 底图更新使用普通 revision，不参与同帧提交；下一次场景切换或清屏时生效。

### 4.4 保存即时生效

设置保存生成新 revision。在线节点立即应用；离线节点保存待生效。图像调节和底图属于显示参数，可以异步应用；白名单变化会影响信号可选性，必须在页面刷新前完成校验。

## 5. REQ-2026-0004 端口绑定

### 5.1 数据模型

`dvs_binding` 一条记录表示“某墙的某格位由某节点的某输出口驱动”。节点级约束通过 `unique(node_id)` 保证一台输出盒只属于一面墙。

### 5.2 能力上报

节点注册时上报：

```json
{
  "role": "output",
  "outputPorts": [
    {"id": "hdmi0", "maxWidth": 7680, "maxHeight": 4320, "maxRefresh": 60,
     "presets": ["1080p60", "2160p60"], "hdcp": "unknown"}
  ],
  "inputPorts": [],
  "maxDecodeSessions": 8,
  "maxLayers": 8,
  "ptp": {"supported": true, "hwTimestamp": false, "state": "synced"},
  "mtl": {"backend": "native_af_xdp", "version": "26.09"}
}
```

平台只用上报值渲染可用格位和端口，不用页面硬编码。

### 5.3 待生效

保存绑定时生成 revision：

- 在线节点：校验端口空闲、格位未占用、节点未绑其它墙，立即下发媒体引擎建立接收会话。
- 离线节点：写入 `pending`，页面区分“期望绑定”和“当前生效绑定”。
- 节点回线：上报 `applied_revision`，平台只下发最新未过期 revision。

绑定变化会改变节点的格位归属，进而影响窗口拆分。平台需要在同一个 operation 中重算受影响窗口并下发新布局。

## 6. REQ-2026-0005 场景管理

### 6.1 快照模型

场景快照只存窗口集合和音量：

```json
{
  "volume": 80,
  "windows": [
    {"id": "w1", "signalId": "in01-hdmi1", "x": 0, "y": 0, "w": 3840, "h": 2160,
     "z": 10, "muted": false}
  ],
  "layoutMode": "free",
  "baseImageRevision": 7
}
```

运行态窗口与快照的差异就是“未保存改动”。平台比较窗口集合、几何、层序、静音和音量。

### 6.2 场景切换

场景切换是严格同帧 operation，流程：

```text
平台                         节点
 |-- create operation ---------->|
 |-- prepare(revision, snapshot) |
 |                               |-- 复用或创建 RX 会话
 |                               |-- 预解码首帧
 |                               |-- 分配 DRM 图层
 |                               |-- 计算本地布局片段
 |<-- ready / blocked -----------|
 |-- commit(apply_at) ---------->|
 |                               |-- 在全局帧边界切换
 |<-- applied(revision) ---------|
 |-- 聚合全部回执，更新当前场景 --|
```

关键约束：

- 任一绑定节点离线、未注册、时钟未同步或准备失败，整墙进入 `blocked_offline`，保持原场景。
- `apply_at` 由平台在全部 ready 后生成，建议为当前时间加 2–3 帧保护带。
- 节点按 `(wall_id, revision)` 幂等处理，低于当前 revision 的命令拒绝。
- 失败后重试生成新 operation。

### 6.3 预解码与关键帧

如果场景中的信号源尚未订阅，节点在 prepare 阶段加入组播并等待可解码帧。H.264/HEVC 需要关键帧才能开始解码，GOP 过长会拖慢切换。

可选策略：

1. 输入编码器使用短 GOP（例如 0.5–1 秒）或周期 IDR。
2. 对切换频繁的墙使用全 intra 编码，带宽换切换速度。
3. 节点常驻订阅该墙白名单内的全部信号，场景切换只改布局。代价是解码通道和带宽。
4. 使用 JPEG XS 等低延迟帧内编码，硬件支持时优先。

V1.0 建议采用“白名单内常驻订阅 + 短 GOP”组合，先保证切换体验，再按实测优化资源。

### 6.4 默认场景

新建墙自动创建一个默认场景，包含空窗口集合和默认音量 80。默认场景可重命名，生效时不可删除。

## 7. REQ-2026-0006 开窗与信号源调度

### 7.1 全局坐标与本地片段

定义整墙像素坐标系：每个格位有 `(cellX, cellY, cellW, cellH)`。窗口矩形 `W = (x, y, w, h)` 位于该坐标系。

节点可能绑定一个或多个格位。对节点 N 的每个格位 C：

```text
inter = intersect(W, C)
if inter is empty: 跳过
localDst = (inter.x - nodeOriginX, inter.y - nodeOriginY, inter.w, inter.h)
srcCrop = (
  (inter.x - W.x) / W.w * srcW,
  (inter.y - W.y) / W.h * srcH,
  inter.w / W.w * srcW,
  inter.h / W.h * srcH
)
```

节点用 DRM plane 的 `src_x/src_y/src_w/src_h` 做源裁剪，用 `crtc_x/crtc_y/crtc_w/crtc_h` 做目标摆放，RGA 负责缩放和色彩转换。

整数边界规则：

- 左、上边界向下取整，右、下边界向上取整，保证相邻节点无缝。
- 所有节点使用同一套取整函数，避免 1 像素接缝。
- 显示设备的 overscan 需要校准；校准值作为节点配置的一部分。

### 7.2 窗口与图层

- 自由模式：窗口可重叠，按 z-order 从低到高排列。
- 固定模式：平台把窗口吸附到格位边界，一格一窗。
- 单节点图层上限由 `capabilities.maxLayers` 决定。超过硬件 plane 数时，节点用 GPU/RGA 把多个窗口合成到一个 framebuffer，再作为一个 plane 输出。
- 最小尺寸 1/16 格、等比缩放、Shift 自由拉伸都由平台在坐标计算时处理，节点只执行最终矩形。

### 7.3 打开窗口的媒体动作

1. 平台校验格位已绑定、信号在白名单、信号在线。
2. 平台把全局窗口拆成每节点片段。
3. 对每个目标节点生成布局 revision。
4. 节点确保该信号的 RX 会话存在；不存在则加入组播、创建解码器。
5. 节点创建或更新 DRM plane，设置源裁剪、目标矩形、z-order、可见性。
6. 单节点窗口可以立即生效；跨节点窗口走 prepare/commit 同帧流程。

### 7.4 音频

- 每个窗口有静音标志；场景有 0–100 音量，默认 80。
- 平台计算音频归属：最新打开且未静音的窗口获得声音，其余自动静音。
- 节点只把获得音频归属的 ST2110-30 流送到 ALSA，并按场景音量做增益。
- 静音只影响音频，不影响视频窗口显示。
- 多路音频同时到达时，节点侧仍需本地仲裁，防止平台状态延迟导致叠音。

### 7.5 信号源面板

信号源来自白名单内输入盒的采集口，显示“设备别名 + 端口号”。在线状态来自心跳和媒体流状态。输入盒离线时信号置灰，已开窗口保留并显示“信号源已离线”占位，不自动关窗。

## 8. REQ-2026-0007 一键清屏

清屏是布局 operation 的特例：

- 节点把所有窗口 plane 设为不可见，保留底图 plane。
- 不修改场景快照，不清空当前场景名，不产生未保存改动。
- 幂等：重复清屏返回首次结果。
- 跨节点清屏同样走 prepare/commit；任一目标节点异常则整墙阻止。
- 清屏后重新开窗，重新计入未保存改动。

实现上可以复用场景切换的下发通道，payload 为“空窗口集合 + 保留底图”。

## 9. REQ-2026-0008 节点角色与信号配置

### 9.1 节点软件分层

```text
节点本机 Web 页
      |
节点代理（HTTP/WS、认证、配置状态机、注册、心跳）
      |
媒体引擎（V4L2、MPP、RGA、DRM、ALSA、MTL）
      |
Linux 内核（V4L2、DRM/KMS、ALSA、网络、PTP）
```

### 9.2 角色

| 角色 | 媒体链路 |
| --- | --- |
| 输入盒 | V4L2 采集 → RGA 转换 → MPP 编码 → ST2110-22 TX（音频 ST2110-30 TX） |
| 输出盒 | ST2110-22 RX → MPP 解码 → RGA 缩放/裁剪 → DRM 合成 → HDMI 输出 |

角色切换必须走受控作业：

```text
影响检查（平台统计绑定、窗口、白名单、未完成 operation）
  -> 平台原子清理（解绑、关窗、移白名单）
  -> 节点写入待生效角色
  -> 重启
  -> 以新角色注册
  -> 能力校验
  -> 成功或回退
```

平台不可达时只保存意图，不重启、不切换。

### 9.3 输入口

输入口按 `capabilities.inputPorts` 枚举，V4L2 设备节点与物理口映射由板级配置提供。单采集口三选一，不提供双口组合。无信号时保存成功，页面显示“无信号”。

### 9.4 输出参数

- 预设分辨率 + 自定义宽/高/刷新率。
- 输出模式：强推、热插拔。
- 强推：无论显示器是否接入，按设定时序输出。
- 热插拔：读取 EDID，跟随显示器最佳分辨率。
- 保存后进入待生效，DRM 模式切换可能导致短暂黑屏，页面提示“重新协商中”。
- 超出 `capabilities` 的值直接拒绝。

### 9.5 本机页

本机页由节点代理提供静态资源，调用 `/api/v1/node/*` 本地接口。认证只在本机校验，默认账号 admin，首次登录提示改密，忘记密码用物理复位键恢复。

## 10. REQ-2026-0009 节点网络、SIP 与运维

| 能力 | 实现 |
| --- | --- |
| 网络 | NetworkManager 或 systemd-networkd；保存后异步应用，断连超时自动回滚旧配置 |
| 注册 | 节点代理向平台注册，携带 SN/MAC/能力/版本；心跳 3 秒，连续 3 次超时判离线 |
| 自动/手动注册 | 自动：应用配置后立即注册；手动：保存后等用户点击注册 |
| SIP | 可选，使用独立 SIP 栈；不可达只影响 SIP 状态，不影响 MTL 媒体链路 |
| 本机信息 | 型号、序列号、固件版本、角色、IP、MAC、注册状态、在线时长、MTL 统计 |
| 重启 | 二次确认，进入 rebooting，节点代理延迟执行 |
| 恢复出厂 | 保留网络和注册地址，重置角色、输入口、输出参数、密码 |
| 升级 | 本地导入固件包，校验清单和 SHA-256，A/B 分区写入，失败保留旧版本 |

SIP 与 MTL 独立。视频墙主链路不依赖 SIP。

## 11. REQ-2026-0010 设备管理

平台侧能力：

- 列表、筛选、别名、在线状态、角色、版本、注册与 SIP 快照。
- 退役：在线先清理绑定、窗口、白名单并等待回执；离线进入 `retire_pending`。
- 墓碑：SN/MAC 保留 30 天，防止重连注册成新设备。
- 批量升级：V1.0 建议串行，最大并发 1；节点失败隔离。

节点侧提供升级接口、进度上报和版本回读。平台不直接改节点配置，节点本机页是配置真源。

## 12. REQ-2026-0011 实时控制与运行可靠性

### 12.1 平台实时框架

| 组件 | 职责 |
| --- | --- |
| Operation service | 创建 operation、生成 revision 和 expires_at、聚合节点回执 |
| Revision store | 每个墙、每个节点维护当前 desired/applied revision |
| Node gateway | 与节点代理的长连接或消息通道，负责下发和回执 |
| Expiry sweeper | 扫描过期 operation，标记 expired，不补发 |
| Audit writer | 记录用户、对象、operation、revision、阶段、结果 |
| Playback task service | 播放任务状态机，调用场景切换 operation |

### 12.2 节点执行器

- 维护每个墙的 desired revision 和 applied revision。
- 收到 prepare：创建会话、预解码、分配图层，返回 ready 或 blocked。
- 收到 commit：按 `apply_at` 排队，在全局帧边界切换布局，返回 applied。
- 旧 revision 只写本地审计，不覆盖运行态。
- 控制通道断开时保持最后布局和最后画面。
- 重连后上报 applied revision，等待平台补发最新 desired revision。

### 12.3 同帧资格

节点上报：

```json
{
  "ptp": {"state": "synced", "offsetUs": 120, "domain": 0},
  "frameClock": {"fps": 60, "epochTaiNs": 1700000000000000000},
  "vsync": {"lastTaiNs": 1700000000123456789}
}
```

平台判定资格：

1. PTP 状态为 synced。
2. 时钟偏差小于阈值，例如 2 ms。
3. 节点在线、已注册、角色正确。
4. 媒体引擎运行且目标信号可解码。

任一不满足则 operation 进入 `blocked_offline` 或 `failed`。

### 12.4 离线保画

- 控制通道断开：节点代理不改变媒体引擎状态，画面保持。
- 媒体流中断：解码器保留最后一帧，DRM plane 继续扫描输出。
- 节点重启：按最后一次 applied revision 恢复布局；若平台不可达，使用本地持久化的最后布局。
- 平台恢复：节点上报状态，平台重建投影；不要求节点重新出画。

### 12.5 播放任务

播放任务是对场景切换 operation 的上层封装：

1. 创建任务，进入 `pending_check`。
2. 校验节点、角色、拼墙、场景。
3. 通过后进入 `pending_execution`。
4. 开始执行时创建场景切换 operation，任务进入 `executing`。
5. 节点回执播放中，任务进入 `playing`，节点上报 `currentPlayback`。
6. 结束、取消、失败或过期后清除当前播放投影，保留任务记录。

同一节点同一时刻只允许一个播放中任务，由平台唯一约束和节点侧互斥共同保证。

## 13. 媒体动作与 MTL API 对照

| 媒体动作 | MTL API / 机制 |
| --- | --- |
| 初始化媒体引擎 | `mtl_init`、`mtl_start` |
| 输入盒发送视频 | `st22p_tx_create`、`st22p_tx_get_frame`、`st22p_tx_put_frame` |
| 输入盒发送音频 | `st30p_tx_create` 及 get/put |
| 输出盒接收视频 | `st22p_rx_create`、`st22p_rx_get_frame`、`st22p_rx_put_frame` |
| 输出盒接收音频 | `st30p_rx_create` 及 get/put |
| 组播加入 | RX ops 中的组播 IP 与 `mcast_sip_addr`，MTL IGMPv3 |
| 运行中换源 | `st22p_rx_update_source` |
| 运行中换目的 | `st22p_tx_update_destination` |
| 指定发送时刻 | `ST22P_TX_FLAG_USER_PACING`、`ST22P_TX_FLAG_USER_TIMESTAMP` |
| 全局帧边界 | PTP 时间 + `ST_EVENT_VSYNC` |
| 零拷贝 | `ST22P_TX_FLAG_EXT_FRAME`、`ST22P_RX_FLAG_EXT_FRAME`、DMA-BUF |
| 冗余 | ST 2022-7 双端口 |
| 统计 | `mtl_get_port_stats`、RX timing parser |

## 14. 实现依赖顺序

```text
平台资源模型（0001/0002）
  -> 绑定与能力上报（0004）
  -> 传输白名单与组播（0003）
  -> 媒体引擎单路收发（0008/0009 的最小闭环）
  -> 单节点开窗与本地布局（0006）
  -> 场景快照与单节点切换（0005）
  -> 跨节点 prepare/commit 同帧（0005/0006/0011）
  -> 清屏与底图（0007/0003）
  -> 播放任务（0011）
  -> 设备管理、退役、批量升级（0010）
```

先把两节点最小闭环跑通，再扩到整墙和多墙。跨节点同帧是最后一块高风险拼图，需要独立验证。

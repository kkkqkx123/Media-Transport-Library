## 1. 技术选型总表

| 项 | 选型 | 拒绝的替代项与理由 |
|---|---|---|
| S-A 切换模型 | 在原 `rx_compositor` 内拆出预建与原子提交两阶段，提交只切 DRM plane 属性，不重建解码器与桥接线程 | 新建合成器替代模块：违反只改原模块约束，且与 mp4_dist 联调分叉 |
| S-A 定时基准 | TAI 纳秒换算为目标帧序号，渲染线程在 vblank 前等待到目标帧 | 用 wall clock 或 sleep 估算：抖动大，无法保证同帧 |
| S-B 会话模型 | 节点侧以源地址端口为键的会话表，命中复用解码链路，未命中走准入淘汰 | 每 commit 重建全部链路：正确但延迟大，且破坏常驻订阅 |
| PTP 状态来源 | MTL 初始化后读取 PTP 时间与端口状态，失败时保持未知并记警告 | 启动前硬编码同步态：虚假上报，误导平台时钟资格判断 |
| T7 平台语言 | C++17 独立工程，落在 `app/dvs_platform/`，与代理同包络协议、同构建链 | Python FastAPI：多余，引入第二运行时与第二依赖链，见 §5 分析 |
| T7/T8 节点网关 | HTTP 注册加轮询心跳沿用，跨节点事务走网关下发的两段式消息，节点复用 IPC 现有状态机语义 | 直接引入 WebSocket 重写注册心跳：收益在 S3 之后，当前增加联调风险 |
| T8 回滚模型 | 平台编排器发新事务回退到上一已提交版本，节点侧复用影子布局恢复 | 节点自治回滚：多节点会出现混合画面，无法收敛 |
| T9 退役模型 | 代理侧软状态加平台侧墓碑表，三十天防重注册 | 直接删节点行：重连会当作新节点注册，产生脏数据 |
| T9 批量升级 | 平台串行编排，单次并发为一，失败隔离，节点侧沿用已有校验加暂存语义 | 并行批量下发：RK3588 链路与电源风险高，失败扩散 |

## 2. S-A 帧边界原子切换

现状：引擎提交通过停止并释放整个合成器再重建实现，画面正确但有黑帧，且解码器重建开销大。布局解析与校验已在执行器侧完成，问题只在提交路径。

选型：保持现有合成器结构与线程模型不变，把一次性的创建逻辑拆成预建与提交两个动作。预建阶段分配 plane、帧缓冲与解码器但不切显示；提交阶段只修改显示属性并在目标帧边界使其可见。影子布局保存在执行器侧，提交失败或收到中止时丢弃预建结果，当前画面不受影响。

修改范围：

- 合成器侧（共享模块，需 mp4_dist 联调回归）：把按流初始化链路的部分拆为可独立调用的预建动作；把启动后只切换显示属性的部分收敛为提交动作；渲染线程增加按目标帧序号等待的能力，到达前保持当前帧输出。
- 引擎侧：在上下文中增加待提交布局与目标帧号字段；提交入口先做白名单与布局校验，再调合成器预建，成功后记录目标帧号并等待提交完成；清空动作走同一提交路径，语义为全 plane 不可见但保留底层。
- 执行器侧：准备动作只做解析校验与影子暂存，不触碰运行中的合成器；提交动作携带目标帧号下发引擎；中止动作丢弃影子；提交失败时引擎内已保留的当前合成器继续出画，由调用方决定是否重试或回滚。
- 桥接层不新增类型，沿用现有钩子表把准备与提交转给执行器，避免 IPC 服务直接依赖引擎头文件。

验证：RK3588 单板四路布局热切无黑帧；中止后画面不变；提交失败后当前画面保持。x86 只做接口一致性检查，不做显示验证。

风险：共享合成器改动影响 mp4_dist 单机播放，需同板回归其原有播放与统计输出无差异。

## 3. S-B 剩余：运行期动态换源

现状：会话准入表已实现白名单校验、命中复用、满员淘汰最久未用，引擎在构建合成器前对每路流做准入。但换源仍需重建整个合成器，常驻订阅语义未形成。

选型：以源地址端口字符串为会话键，lane 下标为复用单位。预建时先查表，命中则复用该路已建链路，仅更新显示几何；未命中则按现有淘汰规则建新链路并刷新使用时间。白名单为空表示允许全部，非空时拒绝非法源并使整次准备失败。

修改范围：

- 准入表模块不变，仅明确其为引擎的唯一会话事实来源，释放接口在布局移除对应源时调用。
- 引擎构建合成器前先做全量白名单预检，任一非法源直接拒绝本次布局，不做部分提交。
- 合成器侧支持按 lane 粒度替换源描述而不重建无关 lane；解码器重建只发生在新源接入时，已有源保持解码连续。
- 执行器解析保持对大小写两种键名的兼容，但新写入统一用一套命名，不保留旧字段双写。

验证：x86 单测覆盖命中复用同 lane、满员淘汰最久未用、释放递减、白名单精确与通配；RK3588 验证单路换源不闪断其余路。

## 4. PTP 与能力收尾

现状：能力探测已实现 DRM 连接器枚举与 plane 数探测，解码并发上限支持环境变量覆盖；PTP 状态与 MTL 版本仍为默认值，等待 MTL 实例可用后回填。

选型：MTL 实例初始化成功后读取 PTP 时间与端口状态并换算偏移，失败降级为未知；MTL 版本取库上报版本，编译期后端宏决定后端字符串。任一子系统不可用只记警告，不中断 IPC 服务。

修改范围：

- 能力模块增加以上线 MTL 实例为输入的刷新动作，由引擎在初始化完成后调用一次，心跳与查询状态读取最新快照。
- 查询状态接口的媒体计数继续由引擎钩子回填，未启动时为零即为真实状态，不做伪造。
- 解码并发上限的最终值以 RK3588 实测为准，当前保守值仅为带板前的占位，实测后改为实测值并移除环境变量覆盖的调试路径。

验证：单板启动后经代理能力接口或直连查询状态确认端口名、层数、PTP 状态与偏移为真实值。

## 5. T7 平台服务（Python 多余，改 C++）

结论：平台用 Python 多余。代理已是 C++17 自研对称网络栈加直编 SQLite，平台是纯控制面，无数据面依赖，引第二语言只增加运行时、依赖链与部署负担，不带来能力收益。平台与代理统一用 C++17 同一构建链，复用已有包络与状态机语义。

依据：

- 现状复用度高：代理已有轻量 HTTP 服务与客户端、SQLite 键值状态机、注册心跳、统一包络，平台所需接口多为其超集，换语言等于重写一遍。
- 部署约束：现场离线，Python 的 pip 与虚拟环境增加版本冻结与离线交付成本；C++ 静态链接沿用现有链，无新增运行时。
- 性能无压力：节点模拟器多代理注册心跳聚合在 C++ 下是轻负载，无需 Python 生态。
- 前端策略不变：复制原型为只读基线，新增真实适配器覆盖模拟接口，页面逻辑不动。

与 ZLMediaKit 的关系（只取所需，不整库引入）：

- 不复制：`3rdpart/sqlite3` 已与代理直编版本一致（同为 3.45.1，经比对一致），无需复制，只需在文档注明版本对齐；`3rdpart/jsoncpp` 不引入，代理与媒体引擎统一用 json-c，避免双 JSON 库。
- 按需复制：`3rdpart/ZLToolKit` 中只取事件驱动所需的网络与线程基础（TcpServer、Socket、EventPoller、线程池与常用工具），用于替换代理当前每连接独立线程的简易服务模型，补齐长连接、复用与 WebSocket 升级能力；媒体相关目录一律不取。
- 只作参考不复制：`server/` 下的主程序生命周期、WebHook 回调、系统与进程管理、命令解析思路，作为平台网关与操作服务的结构参考，代码按本仓包络重写，不原文搬运。
- 约束：全量引入 ZLToolKit 与媒体服务会违反资源紧张与避免多余编译的要求，故只允许上述最小子集，且以独立目录加 meson 条目方式接入，不改代理现有链路。

修改范围：

- 新建 `app/dvs_platform/` 独立 meson 工程（C++17），依赖与代理一致（json-c、线程库、直编 SQLite）。初期直接引用代理已验证的服务与客户端源文件方式复用（与媒体引擎复用 mp4_dist 副本的 fallback 策略一致），出现第三个消费方时再按职责抽公共模块，不预先抽象。
- 数据模型：分组、墙、场景、绑定、白名单、节点快照、播放任务与审计事件，字段命名与原型存储对齐，存储层统一用像素坐标。
- 接口层：实现原型已定义的节点与播放任务路由与统一包络，错误码补齐媒体项；分组拼墙场景绑定等原型只在浏览器维护的部分新增服务端接口，以数据建议文档为基线。
- 网关：接收代理注册与心跳，透传媒体查询状态，转发准备提交中止指令并收集回执；离线判定沿用连续超时语义。WebSocket 只在网关需要服务端推送时引入，注册心跳本身不重写。
- 布局计算：格位快照与像素窗口双向换算，窗口按节点可见矩形拆分为片段，交集裁剪与取整规则集中在此模块，节点侧只做执行。
- 操作服务：单节点先闭环立即生效与离线待生效，跨节点事务留给 T8。

验证：x86 构建平台服务加单测，节点模拟器模拟多代理注册心跳，接口耗时达标；端到端需两节点实测建组建墙绑定开窗保存场景。

## 6. T8 跨节点事务与帧对齐

目标：多节点同一版本同时切换，任一节点失败整体回退，不出现混合画面。

选型：平台编排器驱动全局版本号与操作号，节点两段式执行并支持目标帧号延迟切换。时钟资格以同步态、偏差阈值、纪元与帧率一致为准，不满足时整墙拒绝并保持原场景。

修改范围：

- 平台操作服务增加准备屏障：全员就绪才下发带目标帧号的提交，目标帧号取当前时间加保护带换算；收集回执，任一失败或超时即下发回退到上一已提交版本的新事务。
- 节点执行器与引擎透传目标帧号，合成器在目标帧前一垂直空白期原子切换显示属性；回执携带帧序号与实际时间戳与布局哈希。
- 底图下发按节点格位并集拆分子图，引用版本号异步生效，不阻塞普通版本切换。
- 白名单常驻订阅与淘汰策略按实测调整，换源等待时间以同帧偏差指标为准调保护带与分组包时长。

验证：多板同墙跨格窗口无缝；千次场景切换同帧偏差达标；时钟未同步或节点离线时整墙拒绝且原场景保持；提交失败自动回退无混合画面。全部需硬件。

## 7. T9 退役墓碑批量升级压测与文档

现状：容量自上报已实现并实测；退役只有节点侧软状态；批量编排与墓碑未做。

选型：退役分两步，先在线清理绑定窗口白名单并等回执，再置软状态；墓碑由平台保留防重注册；批量升级串行单并发失败隔离；压测用节点模拟器。

修改范围：

- 代理维护模块增加退役与墓碑软状态，恢复出厂保留网络与注册相关字段，重置角色与输入输出与密码状态。
- 平台增加墓碑表与退役编排，批量升级按单并发下发并回传进度事件，失败节点隔离不影响其余。
- 统计落库把心跳聚合的媒体会话投影写入服务端表，供排障查询。
- 文档回写三处：前端集成计划的状态、应用说明的共享代码节、代理说明的选型与自治行为，与代码一致后关闭本计划。

验证：退役重连命中墓碑；升级包校验失败版本不变可重试；模拟器多节点注册心跳操作聚合达标；多板扩墙回归同帧指标。

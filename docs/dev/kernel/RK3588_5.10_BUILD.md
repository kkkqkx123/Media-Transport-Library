# RK3588 5.10 BSP 编译说明（6.1 对照实验）

> 目的：6.1 镜像（`/data/kkkqkx/rk3588bsp`，kernel-6.1 6.1.118）在 CM588 上表现为
> **UART3 调试串口无输出 + 有线网络不可达**。用 5.10 树（`/data/kkkqkx/rk3588_5.1_XDP`，kernel 5.10.226）
> 编同构镜像做对照，判断是内核版本差异还是板级/驱动差异。
>
> 6.1 侧的网络/串口补丁与结论见 `RK3588_NETWORK_CONFIG_AND_ETH0_STATIC_IP.md`、
> `RK3588_TTYS3_CONSOLE_ENABLE.md`；本文件只讲 **5.10 树怎么编**。
>
> 硬件前提（实测）：板上**只有 UART3（TTL）** 可作调试口，UART2 FIQ debug 未引出；
> 两个 RJ45 是 PCIe **yt6801**，`&gmac1` 必须保持 `disabled`（会抢 uart3 的 GPIO3_B5/B6）。

## 2. 改动点（当前 5.10 工作区已落地的部分）

已落地：§2.1（DTS 双 console）、§2.2（yt6801 驱动拷贝 + Kconfig/Makefile 接线）、
§2.4（u-boot 保 console，**没有它串口一定静默**）。
待落地：§2.3（rootfs 侧网络配置）。

### 2.1 双 console（板级 DTS）

5.10 的板级 DTS 原本没有 `chosen`，bootargs 来自 `rk3588-linux.dtsi` 的 `console=ttyFIQ0`。
在 `ztl-rk3588-cm.dts` 的根节点 `model`/`compatible` 之后插入（完整文件见
`patches/rk3588-5.10/base/kernel/arch/arm64/boot/dts/rockchip/ztl-rk3588-cm.dts`）：

```dts
	chosen {
		bootargs = "earlycon=uart8250,mmio32,0xfeb50000 console=ttyS3,115200 console=ttyFIQ0 irqchip.gicv3_pseudo_nmi=0 root=PARTUUID=614e0000-0000 rw rootwait rcupdate.rcu_expedited=1 rcu_nocbs=all";
	};
```

要点：
- `console=` 顺序决定 `/dev/console`：最后一个（`ttyFIQ0`）仍是 shell 口，`ttyS3` 只作第二日志口。
- `ttyFIQ0` **不写波特率** = 1500000；`ttyS3` 显式 115200。
- 本板 FIQ 口未引出，所以真正能看日志的是 `ttyS3`——它不通就等于"串口完全无响应"。
- 不要靠打开 `&gmac1` 来"多一个网口"，它复用的是 uart3 引脚。

### 2.2 yt6801 驱动移植

5.10 树没有该驱动，必须从 6.1 树搬：

```bash
cd /data/kkkqkx/rk3588_5.1_XDP
SRC=/data/kkkqkx/rk3588bsp/kernel-6.1/drivers/net/ethernet/yt6801
DST=kernel/drivers/net/ethernet/yt6801
mkdir -p $DST && cp -r $SRC/. $DST/
rm -f $DST/*.o $DST/*.a $DST/.*.cmd $DST/modules.order $DST/*.ko
# 接线
sed -i 's|^source "drivers/net/ethernet/3com/Kconfig"|source "drivers/net/ethernet/yt6801/Kconfig"\nsource "drivers/net/ethernet/3com/Kconfig"|' \
    kernel/drivers/net/ethernet/Kconfig
printf 'obj-$(CONFIG_YT6801)\t+= yt6801/\n' >> kernel/drivers/net/ethernet/Makefile
```

驱动本身自带版本保护（`eth_hw_addr_set` 有 `>= 5.17` 条件、`netif_napi_add_weight` 有
`>= 5.18` 条件），**5.10 上 8 个 .c 全部可编译通过**，不需要改驱动源码。

> ⚠️ **必须内建 `=y`，不能 `=m`**：`fuxi-gmac-common.c` 用了 `late_initcall(yt6801_rename_netdevs)`，
> 模块编译时 `late_initcall` 会退化成 `module_init`，与 `fuxi-gmac-pci.c` 的
> `module_pci_driver()` 撞成 `multiple definition of 'init_module'`。
> `ztl_rk3588.config` 片段里就是 `CONFIG_YT6801=y`，走正常构建即可。

`CONFIG_YT6801` 由板级片段打开，而片段只在构建脚本里合并；**手动 `make ztl_defconfig`
不会带上它**（单独验证驱动时可 `./scripts/config -m YT6801` 只做编译检查）。

### 2.3 网络配置（rootfs 侧）

- 6.1 用的 `buildroot/board/rockchip/rk3588/fs-overlay/etc/init.d/S45static-net` 思路可复用
  （按驱动 + PCI BDF 绑定，不按名字）。
- **但 5.10 树的 `rockchip_rk3588_defconfig` 没有把 `board/rockchip/rk3588/fs-overlay`
  加进 `BR2_ROOTFS_OVERLAY`**（只有 `rockchip_rk3588_ipc_defconfig` 引了 `fs-overlay-ipc`），
  直接丢文件进去不会进镜像；要用它必须显式接线。
- 搬过来的驱动里有一段 `late_initcall(yt6801_rename_netdevs)`：把所有 yt6801 netdev 按 PCI
  bus 号排序后改名为 `eth0`/`eth1`。`late_initcall` 晚于 PCI probe，所以正常情况下 5.10 上
  网口名是稳定的 `eth0/eth1`；**但若 gmac 先占了 `eth0`，`dev_change_name()` 会失败并打
  `yt6801: rename ... failed` 的 warning**——上板先 `dmesg | grep yt6801` 确认改名结果。

### 2.4 根因：u-boot 会把 DTB 的 bootargs 整个替换掉（2026-10-29 定位）

**只改 DTS 的 `chosen.bootargs` 是无效的。** 链路如下：

1. `u-boot/arch/arm/mach-rockchip/board.c` 里 `board_fdt_chosen_bootargs()`（**强符号**，不是
   `common/fdt_support.c` 的 `__weak` 版本）依次调用 `bootargs_add_dtb_dtbo/partition/fwver/android()`；
2. 本 SDK 的 u-boot `.config` 里 `CONFIG_ROCKCHIP_PRELOADER_ATAGS=y`，`bootargs_add_fwver()` 里
   `list2` 恒非空 → **无条件** `env_update("bootargs", "androidboot.fwver=...")`；
3. `env_update()`（`cmd/nvedit.c`）在变量不存在时**创建**它，于是 env `bootargs` 变成只有
   `androidboot.fwver=...` 之类，**不含任何 `console=`**；
4. `fdt_chosen()`（`common/fdt_support.c:337`）拿到 `env_get("bootargs")` 后
   `fdt_setprop(chosen, "bootargs", str, strlen(str)+1)` —— **整体覆盖**，DTS 里的
   `console=ttyS3,115200 console=ttyFIQ0` 全部丢失；
5. 结果是内核命令行里一个 `console=` 都没有 → **内核不注册任何 console → 串口完全静默**。

这也解释了为什么 6.1 与 5.10 表现一致：两者用的是同一份 u-boot，所以和内核版本无关。

修复（`u-boot/arch/arm/mach-rockchip/board.c`，`board_fdt_chosen_bootargs()` 的 `return` 前）：

```c
	env_update("bootargs",
		   "console=ttyFIQ0 console=ttyS3,115200 earlycon=uart8250,mmio32,0xfeb60000");
	/* env_update() may reallocate, refresh the pointer */
	bootargs = env_get("bootargs");
```

- `ttyS3` 放**最后** → `/dev/console` 落在 UART3（本板 UART2 FIQ 未引出），systemd 的
  `systemd-getty-generator` 会据此在 ttyS3 上起 getty。
- `earlycon` 指 **0xfeb60000（uart3）**，不是 0xfeb50000（uart2）。
- `bootargs` 指针必须在 `env_update()` 之后重新取，否则可能指向已被释放的旧值。
- DTS 里的 `chosen.bootargs` 同步改成同样的串（作为没有该 u-boot 行为时的 fallback）。

> u-boot 自己的串口日志走 UART2（`CONFIG_BAUDRATE=1500000`），板上未引出，所以烧录后
> UART3 上**从内核 earlycon 开始**才有输出，看不到 u-boot/loader 阶段。

## 3. 构建命令

### 3.1 选板（一次性，非交互）

```bash
cd /data/kkkqkx/rk3588_5.1_XDP
./build.sh rockchip_rk3588_ztl_cm588_defconfig
```

`./build.sh` 不带参数会走交互式 `choose_defconfig`；带上 `*_defconfig` 精确匹配即可跳过交互。
生成 `output/.config`，关键项：

```
RK_KERNEL_CFG="ztl_defconfig"          RK_KERNEL_CFG_FRAGMENTS="ztl_rk3588.config"
RK_KERNEL_DTS_NAME="ztl-rk3588-cm"     RK_USE_FIT_IMG=y
RK_DEBIAN_VERSION="bullseye"           RK_DEBIAN_ARCH="arm64"
RK_DEBIAN_MIRROR="mirrors.ustc.edu.cn" RK_PACKAGE_FILE_CUSTOM=y
```

### 3.2 内核（2026-10-28 实测通过）

```bash
./build.sh kernel        # 编 Image + dtb，打包 FIT boot.img
```

产物 `kernel/boot.img`（FIT，实测 49 MB）→ `output/firmware/boot.img`。

⚠️ 首次编译前必须放 Mali CSF 固件（见 §2.4），否则 `mali_kbase_csf_firmware.o` 报
`file not found: drivers/gpu/arm/bifrost/mali_csffw.bin`。

### 3.3 rootfs：Debian bullseye XFCE（2026-10-28 实测通过）

**网络下载单独先做**（`mk-base-debian.sh` 走 live-build 的 qemu 引导，最耗时，且与内核编译无关）：

```bash
cd debian
RELEASE=bullseye TARGET=xfce ARCH=arm64 ./mk-base-debian.sh
# 产物 debian/linaro-bullseye-alip-YYYYMMDD-1.tar.gz（实测 613 MB）
cd ..
./build.sh debian        # 复用上面的 tarball，不再下载
```

产物 `debian/linaro-rootfs.img`（实测 3.7 GB）→ `output/debian/images/rootfs.ext4` → `output/firmware/rootfs.img`。

`build_debian()` 把 `TARGET` 写死成 `desktop`，所以 XFCE 必须先手工生成 base tarball；它只检查
`linaro-$RK_DEBIAN_VERSION-alip-*.tar.gz` 是否存在，存在就跳过下载。内部流程：

1. 无 tarball → `RELEASE=bullseye TARGET=desktop ARCH=arm64 ./mk-base-debian.sh`
   （`debian/ubuntu-build-service/bullseye-desktop-arm64`）；
2. `VERSION=debug ARCH=arm64 ./mk-rootfs-bullseye.sh`（解压到 `debian/binary`、跑 `overlay`、chroot 装包）；
3. `./mk-image.sh` → `debian/linaro-rootfs.img`。

### 3.4 补齐其它分区（必须，否则打包失败）

`./build.sh debian` **不会**生成 loader/uboot/misc/recovery；直接打包会遇到
`Error:<AddFile> open file failed,err=2!`。按顺序补：

```bash
./build.sh uboot      # u-boot + rkbin → MiniLoaderAll.bin、uboot.img（有 prebuilts，实测约 1 分钟）
./build.sh misc       # misc.img（空镜像）
./build.sh recovery   # recovery.img（buildroot 全量，最慢；首次约 30-60 分钟）
```

### 3.5 打包

```bash
./build.sh firmware    # 收集/校验 output/firmware（其 post hook 会顺带调一次 mk-updateimg）
./build.sh updateimg   # 产出 output/update/Image/update.img
```

分区（`parameter-rk3588-ztl.txt`）：`boot` = `0x40000@0x00008000`，`rootfs` = `-@0x00111000(rootfs:grow)`；
`package-file` 里 rootfs 取 `rootfs.img`。只换 rootfs 时可只刷 `rootfs` 分区。

### 3.6 一次全量

```bash
./build.sh            # 99-all.sh：loader → uboot → kernel → rootfs → updateimg
```

长任务用 `setsid` 脱离会话，日志落盘后轮询（与 6.1 文档一致）：

```bash
setsid bash -c "./build.sh kernel > /tmp/build-kernel.log 2>&1" < /dev/null &
```

## 5. 不上板的构建侧校验

```bash
cd /data/kkkqkx/rk3588_5.1_XDP
```

## 6. 已知约束与坑

| 现象 | 原因 / 处理 |
|---|---|
| `multiple definition of 'init_module'` | `CONFIG_YT6801=m`；改 `=y` |
| 5.10 上 `ip link` 看不到两个 RJ45 | 驱动没搬 / `CONFIG_YT6801` 被丢弃；查 `nm vmlinux \| grep fxgmac` |
| ttyS3 完全静默（**最常见的真因**） | u-boot 的 `board_fdt_chosen_bootargs()` 用 env `bootargs` 覆盖了 DTB 的 `chosen`，`console=` 全丢 → 内核无 console。必须按 §2.4 改 u-boot；只改 DTS 无效 |
| ttyS3 仍无输出（已按 §2.4 修过） | ① 打开了 `&gmac1`（抢 GPIO3_B5/B6）；② 接线取自 232/485 侧而非 TTL；③ 波特率不是 115200；④ 板子 TTL 口的 TX/RX 需要交叉 |
| 把脚本丢进 `buildroot/.../fs-overlay` 却不生效 | 该 defconfig 未引用该 overlay，需加 `BR2_ROOTFS_OVERLAY+=` |
| `./build.sh` 卡在 "Pick a defconfig" | 用 `./build.sh rockchip_rk3588_ztl_cm588_defconfig` 指定，或非交互环境避免无参调用 |
| `ls -lh output/firmware/update.img` 只有 26 字节 | `firmware/` 下全是软链；用 `ls -lL`，或直接看 `output/update/Image/update.img`（实测 3.8 GB） |
| `pgrep -f "build.sh recovery"` 一直显示 RUNNING | 匹配到了 ssh 命令自身；用 `ps -eo cmd \| grep -v grep` 或只看日志尾部的 `build_recovery succeeded` |
| Debian rootfs 起来后网口没地址 | 该 rootfs 由 **NetworkManager** 管（`/etc/systemd/network` 为空），上板用 `nmcli` 手动配；`nmcli device status` 先确认两个 yt6801 口 |

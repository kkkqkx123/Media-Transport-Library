# DVS 配置覆盖度修复设计

## 背景

需求映射把平台资源模型、节点本机配置、媒体会话参数定义为三端契约。
现状三端已经跑通最小闭环：平台文档存储加按种校验、操作屏障加扇出、
代理六域状态机加布局翻译、媒体影子交换加帧边界提交。
本设计补齐控制面已经承诺但数据面尚未接通的配置，保证失败快返、
同帧语义与离线保画不受影响。

## 需要支持的配置

平台侧维护分组、拼墙几何与格位、场景快照、绑定、白名单、底图与图像调节、
操作版本与统一生效时刻、播放任务、节点注册与心跳、退役墓碑与升级。
拼墙固化整墙像素与格位矩阵、时间纪元与帧率；场景只存窗口集合与音量；
绑定表达墙格位与节点输出口的归属；白名单表达每个信号的组播地址端口、
源过滤、编码参数与音频端口；操作携带版本、生效时刻、帧号与布局哈希。

节点侧维护角色、采集输入、显示输出、系统网络、注册、会话信令六域，
每域保存期望值、期望版本、生效版本与失败原因。
输入域保存采集口、编码参数与发送目标；输出域保存接口、分辨率刷新率与模式；
网络域保存寻址方式与连通检查目标；注册域保存服务器与模式。
本机页是单机真源，平台只下发几何与角色子集。

媒体侧维护发送会话、接收会话、布局片段、音频归属、底图与调节、时钟。
发送会话保存采集口、编码与目标；接收会话保存组播组、源过滤与解码状态；
布局片段保存节点本地目标矩形与源裁剪；音频保存归属窗口与音量；
时钟保存同步状态、偏差、纪元与帧率。

## 现状评价

合理的部分继续保留。
平台独占像素取整与几何冻结，节点不重复计算。
绑定待生效在注册与心跳时提升，端口与格位冲突在保存时拒绝。
扇出按成员几何切分， barrier 校验通道就绪、帧一致与时钟资格，
失败回滚到上一个已提交快照。
代理翻译把窗口标识解析为通道序号，音频无归属时本节点静音。
媒体影子准备加帧边界交换，失败保留旧画面。
网络应用带快照与连通检查，失败回滚。

缺口集中在参数透传与命名一致。
白名单已存编码分辨率帧率码率与关键帧间隔，但扇出只带地址端口帧率，
翻译只能把窗口尺寸当作信号分辨率，源裁剪缺少到信号像素的换算。
编码命名在白名单与发送会话两侧不一致。
场景保存时只做全局下限检查，墙级下限只在准备时检查。
操作超时时间只存平台侧，未随布局下发，节点无法本地过期。
上述缺口均可加字段方式补齐，不改变现有消息主干。

## 修复思路

端到端参数透传采用加字段策略，未携带时保持旧行为。
白名单编码参数随扇出进入端点表，代理翻译时优先使用信号原生分辨率，
把窗口像素的源裁剪按比例换算到信号像素，发送给引擎的帧尺寸即信号尺寸。
端点缺编码参数时回退到窗口尺寸，保证旧数据与单测继续通过。
编码取值在两侧统一，发送侧把常用别名视为同一编码，混合编码的墙在翻译时直接拒绝，
避免单解码器类型被静默误用。
场景保存时补墙级下限检查，与准备时共用同一函数。
操作超时随布局下发，代理在准备阶段检查过期，引擎在提交阶段复查过期，
过期一律按准备失败处理，触发整墙阻止与回滚。

## 任务划分

先补端点媒体参数透传与翻译换算，这是画质与解码正确性的前提。
再统一编码命名与混合编码拒绝，保证失败快返。
接着补场景墙级下限检查，把准备时失败提前到保存时。
然后补超时下发与两端检查，关闭控制与媒体时钟不一致的窗口。
最后回写本文与相关接口说明，保持文档与代码一致。

## 验证

单节点单窗口验证信号分辨率与源裁剪换算，混合编码验证拒绝路径，
大格位墙验证小窗口在保存时被拒绝，超时注入验证整墙阻止与回滚，
旧白名单缺字段验证回退行为不变。
后续仍用既有两节点闭环与长时间运行验证同帧偏差与稳定性，
本文不再另立验证体系。

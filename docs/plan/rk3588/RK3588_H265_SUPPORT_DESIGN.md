# RK3588 H265 编码支持设计

## 背景与现状

MTL 库传输层天然支持 H265 码流（`ST22_CODEC_H265 / H265_CBR`，`ST_FRAME_FMT_H265_CODESTREAM`），ST22 帧级传输走不透明码流透传，与编码类型无关。`dvs_media` 控制面也已透传 `h264,h265`（能力上报、会话校验、后端映射）。

TX 发送侧已完整：MPP 编码器按配置选择 AVC/HEVC 类型，H265 使用主档配置并复用既有码控、GOP、QP 热更新路径；文件源按流编码选择对应解复用过滤器，参数集区分 AVCC 与 HVCC 解析为 AnnexB，IDR 识别与拼接按编码类型区分；SEI 时间戳载荷保持 25 字节不变，仅 NAL 头区分，H264 沿用单字节头，H265 使用双字节前缀 SEI 头；发送侧 H265 跳过 H264 专用的 SPS VUI 重写；接收桥对两种 SEI 都尝试剥离。

此前真正的缺口在 RX 接收侧的编码选择：解码器与预处理都已是编码感知的，但 `file_playout` 配置中没有编码选项，合成器与单流管线的编码参数恒为零值即 H264，配 H265 流会建错解码器。本次修改补上该接线：接收配置新增编码选项，缺省保持 H264，经合成器与单流管线透传到解码器创建；`dvs_media` 引擎在构建合成器时透传同一配置，静态配置即可选 H265。

宿主机 `D:\project\embedded\zlmediakit` 在本编译环境不可见；以下 H265 事实以 ctx7 查询的 ZLMediaKit 上游实现与 Rockchip MPP 编码器文档为依据。

## 参考依据

* ZLMediaKit：`H265Frame` 按首 NAL 分类（`VPS/SPS/PPS/AUD/前缀后辍 SEI/IRAP` 其中部分为 IDR），未就绪或首 NAL 为参数集/SEI 时按 start-code 切分，逐 NAL 处理。本项目为 ST22 整帧传输，无需 RTP FU 分片，只借用其 AnnexB 切分与分类规则。
* MPP：编码器通过配置字符串键区分 H264 与 H265 档位、层级、类型，初始化编码类型需与配置一致。FFmpeg 复用侧按编码类型选择对应的 MP4 转 AnnexB 过滤器（AVCC 与 HVCC 分别处理）。

## 目标与非目标

目标：编码发送侧可选 H265，文件源 H265 MP4 可发送，接收解码侧按配置可解 H265，端到端 SEI 时间戳可用；单机 TX 配置、文件播放管线与 `dvs_media` 静态配置均新增编码选项，缺省保持 H264。

非目标：多码流混合按流编码自适应（合成器本期仍为全 lane 单一编码，后续信令携带每流编码时再扩展）；H265 VUI 色彩重写（本期直通，依赖 MPP 与采集端默认）；B 帧与 SVC 分层。

## 方案

编码器按配置选择 MPP 编码类型，H265 主档配置保持与 H264 相同的码控、GOP、QP 热更新路径。SEI 时间戳载荷不变，仅 NAL 头按编码区分。参数集处理区分 AVCC 与 HVCC，创建时自适应解析为 AnnexB，IDR 拼接与预处理按编码类型识别关键帧。解复用按流编码选择对应过滤器。发送侧 H265 跳过 H264 专用的 SPS VUI 重写。接收配置新增编码选项并透传到解码器创建，引擎构建合成器时透传同一配置。

## 验收

编码侧产出可用 HEVC AnnexB 码流并经 ST22 整帧传输，解码侧按配置正常出帧；H264 回归行为不变；未知编码明确拒绝；接收缺省仍为 H264。

## 后续

合成器按流编码选择解码器；H265 VUI 色彩按需补齐；能力协商失败路径的端到端提示；IPC 动态布局携带编码（当前动态布局仍沿用启动配置的编码）。

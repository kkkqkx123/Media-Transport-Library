# 平台与代理通道改造为持久化通道的设计方案

> 基准：`docs/analysis/RK3588_DVS_INTEGRATION_TECHNICAL_SOLUTION.md` 的分层与职责划分，
> 以及 `docs/analysis/dvs_communication_and_separation.md` 与 `docs/plan/DVS_INTER_NODE_COMMS_FIX.md` 已落地的闭环。
> 现状：平台与代理之间为短连接 HTTP JSON 轮询加按需反向回调，代理与媒体之间为 Unix 域套接字 JSON 行协议。
> 本文只讨论平台与代理之间的通道如何从短连接 HTTP 演进到持久化双向通道，不动代理与媒体之间的本地通道，不动媒体数据面。

## 目标与非目标

目标是把注册加心跳加屏障回执加布局扇出加配置下发加串行升级这六类消息收敛到一条由代理主动拨出的持久化双向通道上，让平台可以主动推送，让代理可以流式上报，同时保持现有 JSON 信封语义与 SQLite 落盘语义不变。

非目标是不合并平台与代理进程，不让平台直连媒体引擎，不引入新的运行时重依赖，不做多输出口与固件激活等生产包外任务，不改需求文档原文。

## 现状摘要

当前平台侧常驻逻辑集中在平台主循环的请求分发函数内，注册与心跳负责节点文档写入，准备接口负责登记屏障并发起后台扇出线程逐节点回调代理的布局接口，提交接口负责收集回执并驱动屏障状态机，升级接口负责串行回调各节点。代理侧常驻逻辑是注册心跳后台线程加布局到达后另起后台线程监听媒体事件再回执提交。传输层是共享基础库中的最小阻塞式 HTTP 服务端与客户端，短连接、无复用、无服务端推送、无域名解析、无加密，平台反向回调依赖注册时上报的可达地址。

该形态在受控局域网与少量节点下可用，但在节点增多与弱网下暴露出推送依赖可达地址、心跳粒度粗、扇出结果只记审计而调用方不可见、提交可能永久挂起、升级阻塞请求处理线程等问题。

## 通道选型结论

优先做持久化 WebSocket 加 JSON，暂缓 gRPC。

WebSocket 加 JSON 与现状同构，消息体仍是现有 JSON 信封，只是承载从一次一连接变为一连接多消息。代理主动向平台建链，天然穿透地址转换与防火墙，平台不再依赖可达地址做反向回调。实现上只需在现有套接字代码上补帧编解码与心跳保活，不新增第三方运行时，符合平台直编 SQLite 且无新增运行时依赖的约束，也符合无外网下载依赖的部署约束。

gRPC 意味着引入 HTTP2 加数据接口描述加代码生成加 TLS 证书体系，构建链与交叉编译成本明显上升，与现有动态 JSON 契约差异大，且千兆局域网内小消息的性能收益有限。仅在需要强接口契约、多语言网关、细粒度流控与双向流式背压成为瓶颈时再评估，本文只给出兼容接口映射，不作为本次实施路径。

## 目标拓扑

保持星形拓扑与进程隔离不变。代理作为拨出方与平台建立一条常驻连接，断线由代理负责重拨。平台持有连接注册表，键为节点标识，值为连接句柄与传输类型。同一节点在过渡期内可能同时存在轮询记录与长连接记录，以长连接为准，轮询仅作兜底。媒体引擎仍只接受代理经本地套接字的控制，不感知通道变化。

## 消息映射关系

现有接口语义全部保留，只是换承载。注册对应连接建立后的首次问候，携带与现有注册体相同的序列号与硬件信息与几何与能力与网络信息。心跳对应周期上行消息，携带与现有心跳体相同的运行状态与 lane 摘要与发送端摘要与探测摘要。布局下发对应平台经长连接下行的准备消息，携带与现有布局接口相同的操作标识与版本与生效时间与几何与窗口分片。提交回执对应代理经长连接上行的屏障回执，携带与现有提交接口相同的操作标识与节点与状态与 lane 明细。配置下发对应平台下行的配置消息，仅含几何与角色子集，与现有同步接口的过滤规则一致。升级对应平台下行的任务消息，代理分片回传进度与结果，替代现有串行阻塞调用。

每条消息保留现有成功失败信封，新增消息标识用于幂等去重，重复投递返回首次结果而不重复执行。

## 共享契约补充：只补契约，不换传输

传输共享与契约各自为政是现状的准确描述。两端已通过相对路径同源编译共享传输与存储，即代理与平台各自编入同一份传输服务实现与同一份哈希与同一份数据库实现，但信封构造与请求标识生成与字段提取与令牌校验在两边各写一份，成功失败包形状与标识规则已经分叉。因此改造不切换序列化框架，而是在共享基础库内按职责补一块契约职责，与传输职责并列，不做替代性新模块。

该契约职责只收敛三件事。第一是信封形状统一，成功失败的字段集合与状态码来源唯一，请求标识生成规则唯一，不再允许一端固定值另一端自增。第二是六类消息的必填字段表统一，注册问候与周期心跳与布局下发与屏障回执与配置下发与升级任务的字段名与取值范围只定义一次，两端同源编译，缺字段与类型错直接拒绝，不做静默兜底与猜测补齐。第三是鉴权入口统一，握手与短连接回调的令牌校验走同一判定，空令牌含义一致，避免一端严一端松。

该职责归属共享基础库，传输仍只管连接与帧与保活，平台只管编排与投递，代理只管拨号与转发，契约只管形状与校验。命名按所做之事表达，不起替代性名称，不保留旧契约做兼容，不做版本号递增，非法消息直接失败，由调用方修正后重发。

## 连接生命周期

代理启动后先做本地自治判断，平台地址为空则不拨出，与现状一致。地址非空则发起握手，首包携带版本契约与 bearer 令牌，版本不匹配只告警不阻断媒体，令牌缺失或错误则平台拒绝。握手成功后平台登记连接并回传心跳周期与屏障超时等协商参数。双方互发保活，空闲超时由平台先断，代理负责退避重拨，退避带抖动并设上限。平台侧以连续错过若干心跳判定离线，与现有连续三次失败置离线的语义对齐。旧连接重连成功后平台替换注册项并清理过期屏障等待，避免同一节点的双连接重复计数。连接注册表与节点文档分离存放，文档仍是 SQLite 唯一真相，注册表仅为内存索引，重启后靠代理重连重建。

## 屏障与配置与升级在长连接上的行为

准备流程仍由平台登记屏障并计算生效时间与像素分片，但投递从逐节点短连接回调改为经各自长连接下行，投递结果分为已发送与无连接两类，无连接节点记入缺席集合并走现有审计。代理收到准备消息后转调媒体准备接口，仍用现有后台监听事件再回执的流程，只是回执走长连接上行。平台收到回执后驱动现有状态机，任一阻塞仍走回滚描述。新增屏障超时与垃圾回收，超时未齐的屏障按阻塞处理并生成回滚，避免永久停留在准备中。超时值来源于握手协商，默认覆盖两帧加保底，与现有生效时间计算一致。

配置下发仍只下发几何与角色，其余字段忽略并审计。代理落库后经长连接回确认，携带已应用版本，心跳回执也可捎带期望版本，从而补上现有心跳回执忽略已应用版本的缺口。升级改为任务下行加进度上行，平台不再阻塞请求处理线程，逐节点串行语义保留但改为任务队列驱动，失败隔离到单节点。

## 模块改动划分

按职责拆分，不做替代性新模块，不改模块名所表达的职责。

共享基础库负责传输承载，在现有服务端与客户端内部扩展帧处理与保活与握手鉴权，对外保持原有调用形状，新增长连接会话原语。平台负责连接注册与消息路由与屏障投递，把现有准备接口中的扇出线程体改为经注册表投递，把现有升级接口中的同步循环改为任务队列。代理负责拨号与重连与消息分发，把现有注册心跳线程改为长连接上的问候与周期消息，把现有布局接口的处理函数改为长连接消息处理函数，把现有提交回执改为长连接上行。存储与布局数学与操作协调器只做增量增强，存储仍是文档与墓碑与审计，布局仍是平台唯一舍入，协调器新增超时查询与过期清理。

## 安全与配置

沿用现有 bearer 令牌环境变量，不新增校验框架。握手阶段校验一次，连接存续期间不再逐消息校验，令牌轮换靠重连生效。浏览器侧仍用 Cookie 会话，机器间仍用 bearer，互不混用。传输加密作为部署选项，内网默认明文，长连接本身不绑定证书基础设施，避免引入发版外的运维负担。所有新增环境变量提供缺省值，缺省行为与现状一致，空令牌即不校验。

## 迁移与兼容

平台与代理同端口双服，现有短连接接口全部保留，长连接作为新增路径挂在同一端口的流式路径下。代理侧用传输模式环境变量选择优先长连接还是只用短连接，缺省为优先长连接失败回退短连接。平台侧按节点记录实际传输类型，便于灰度与回退。过渡期内两种路径写入同一份节点文档与同一套屏障状态机，不做双写分支。固件上传等大体量传输仍走现有短连接，不挤占控制长连接。回退只需切回传输模式，无需改数据格式。

## 测试与验收

单元层面覆盖帧编解码、心跳保活、幂等去重、屏障超时回收。集成层面起一平台加双代理做建组建墙绑定开窗存场景全流程，覆盖断线重连、超时回滚、无连接节点缺席、令牌错误拒绝、升级进度回传。长稳层面验证断控制网络后媒体画面不黑，恢复后自动重连并追平版本。验收沿用现有单节点多窗口与多节点墙的显示与切换标准，新增通道相关的离线判定延迟与屏障超时上限作为附加指标。

## 风险与不做事项

主要风险是空闲连接被中间设备回收，需要保活周期小于常见回收超时。批量升级的大消息不应阻塞布局与心跳，需要发送队列按消息类型限长，超限丢弃非关键遥测而保留屏障与配置。不做 gRPC 代码生成与证书体系，不做代理与媒体通道替换，不做跨平台网关的多语言桩生成，不引入需要外网拉取的构建依赖。

# DVS P1 细化修改方案

> 基准：当前工作树；缺口口径以 `DVS_P1_P3_REMAINING_GAPS.md` 第 1 章 P1 六项为准，
> 状态真相源为 `BACKEND_STATUS_AND_REMAINING_TASKS.md`（本文写作时以其为准，
> 仅补充本轮审计发现）。
> 本方案只覆盖 P1（单节点媒体引擎）；P2/P3 不在本文范围。
> 约定：修改只改原模块，不新增“版本二”模块；纯解析/纯计算逻辑下沉到
> 无硬件依赖的轻量单元，保证 x86 可单测；凡需 RK3588 实测的项明确标注，
> 代码侧只做到“可测就绪”，不虚报完成。

## 0. 本轮审计结论（与缺口文档的差异）

- 跨格源裁剪渲染链其实已通：`display_layout` 做裁剪合法性校验并写入
  `display_layer.src_*`，`rx_compositor` 透传 `src_*` 且几何快切把裁剪变化
  判为重建，`drm_renderer` 按钳制后的源矩形下发 plane。缺口文档“渲染仍按
  全帧送显”的描述已过时，剩余工作是 prepare 期提前校验与单测覆盖，
  不是渲染重写。
- 音频窗口级仲裁与跟随切换主体已实现（`laneN`/序号/`sip:port`/`sip` 四式
  解析、commit 后按新 lane 重解算、空 owner 静音），剩余问题是未命中 owner
  时的策略：旧订阅继续出声，但上报 `applied=false`，声画状态自相矛盾。
- 能力与健康计数的采集点已存在（compositor lane 统计、准入表快照、PTP 钩子），
  剩余问题是三处纯逻辑散落在桥接层、不可单测：后端名映射在两处重复实现，
  PTP 偏移数学写在钩子闭包里，解码上限只有固定值加 env 覆盖。

## 1. 音频归属与静音策略收尾

现状：`engine/audio_arbiter.c` 负责解析与订阅切换，`engine_ctx` 保存
`audio_owner` 并在每次提交后重应用，上报走 `audio_applied_*` 快照。

剩余问题：owner 命中失败时函数直接返回，正在播放的旧订阅不断，
查询侧却报告未生效；owner 字符串分类逻辑与 compositor 强耦合，
x86 无法单测。

修改方案：

- 新增轻量单元 `engine/audio_owner`，只做 owner 字符串分类（空/静音、
  laneN、纯序号、端点、纯 sip、非法），不依赖 compositor 与 ALSA，
  由仲裁器复用。
- 仲裁器未命中 owner 时主动把音频订阅切到静音再上报失败，保证“上报失败
  即无声”，与静音语义一致；命中失败的快照保留请求 owner、清空 sip/port、
  置未生效。
- 空 owner 的语义保持为静音并把音量归零，不引入“跟随主画面”第二语义，
  避免静音与跟随混淆；窗口切换时的跟随由提交路径重解算同一 owner 实现，
  已存在，不另加机制。

退出标准：非法 owner 换源后无声且查询一致；owner 分类单测全绿。

验证：x86 跑音频 owner 分类单测与 TX 会话单测；RK3588 单板实测窗口切换
跟随与静音。

## 2. 跨格源裁剪 prepare 期校验

现状：渲染与版式链已支持源裁剪（见第 0 章），`layout_executor` 已解析
`srcX/srcY/srcW/srcH`（含 snake_case 兼容），提交期的
`build_compositor` 经 `file_playout_pip_validate` 做最终合法性拦截。

剩余问题：IPC prepare 钩子只校验 sip/port/尺寸/帧率与白名单，不看裁剪
字段，非法裁剪要到 commit 重建时才失败，prepare/commit 两阶段语义被
削弱；裁剪解析无 x86 单测。

修改方案：

- 新增轻量单元 `engine/stream_validate`，提供无硬件依赖的流形状校验
  （必备字段、裁剪越界、零宽高语义），桥接层 prepare 期逐 lane 调用，
  失败直接 400 拒绝，不进入影子布局。
- 提交期保持现有 `file_playout_pip_validate` 为最终权威，不拆弱；
  prepare 校验与提交校验是同一规则的两次执行，不是两套规则。

退出标准：非法裁剪在 prepare 即被拒绝并指明 lane；解析与校验单测全绿。

验证：x86 单测覆盖全帧、合法偏置裁剪、越界、零宽高四类；RK3588 实测跨格
窗口接缝。

## 3. 能力配额与 PTP/backend 真实刷新

现状：`engine/capability.c` 已真实探测 DRM 输出、V4L2 采集口与 plane 数，
`ipc_engine_bridge` 的 PTP 钩子已能从 MTL TAI 与系统 TAI 算偏移，
backend 有按端口前缀的映射，但三处逻辑不可单测或重复实现。

剩余问题：解码上限是 plane 数与写死常量取小再加 env 覆盖，没有 MPP 侧
输入；PTP 偏移数学闭包在桥接层；backend 映射在能力与桥接各写一份。

修改方案：

- 能力侧新增 MPP 上限注入点（默认按 RK3588 公开能力的保守值，env 覆盖
  保留为带内调试手段并注明），静态上限取 plane 上限、合成器 lane 上限、
  MPP 上限三者之小。
- PTP 偏移收敛为纯函数（输入 MTL TAI 有效性与两侧时钟差，输出 state 与
  微秒偏移），桥接钩子只负责读时钟、把数学交给纯函数；单调时钟模式恒为
  unknown。
- 后端名映射收敛到能力侧唯一实现，桥接钩子复用，消除双份前缀表。

退出标准：同一前缀在能力与查询两条路径返回同一后端名；PTP 纯函数单测
覆盖同步、失锁、单调三态；解码上限随注入变化且 env 覆盖仍生效。

验证：x86 单测；RK3588 比对上报值与实测（解码路数、PTP 偏移、backend）。

## 4. `query_state` 健康计数真实化

现状：`dvs_engine_counts` 与 `dvs_engine_lane_stats` 在 compositor 运行时
取 lane 数、就绪数、图层数与每 lane 丢帧/末帧 PTS，空闲时回落到准入表
快照（就绪为假），PTP 与 TX 快照已接真引擎。

剩余问题：lane 条目只有 readiness 一种健康表达，调用方需自行推断是否
正在解码；回落路径的零值与运行路径的字段集不一致。

修改方案：

- lane 条目显式增加解码健康标记（取值与就绪一致），运行与回落两条路径
  字段集对齐，回落路径统一为未就绪、零丢帧、零时间戳。
- 计数刷新保持“持锁快照加原子发布”，不新增锁层级；锁顺序维持现状
  （引擎互斥量先于会话自旋锁之外，不反转）。

退出标准：查询契约在媒体开/关两种状态下字段齐整；大包与回放语义不变。

验证：x86 跑 IPC 协议单测（大包、回放、状态机）；RK3588 比对丢帧与
解码数。

## 5. Input 角色 teardown 补齐

现状：`engine_ctx` 的角色切换、TX 启停、后端启停分散在多个 teardown 点，
后端停止与 TX 会话停止均已幂等，引擎停止可重入。

剩余问题：同角色重复切换仍走完整 teardown，有抖动风险；TX 参数校验只有
 frozen SoC 上限，没有结合上报能力的门控；角色查询与“媒体是否干净”的
 断言缺少统一入口，往返测试无法在无硬件环境下表达。

修改方案：

- 角色切换加同值快速路径：角色无变化直接成功返回，不碰 compositor、
  会话与 TX。
- TX 会话侧新增结合能力上限的纯校验（分辨率、帧率、码率、编码器白名单），
  以显式上限结构体传参，不反向依赖能力模块，保持无硬件可测；引擎保留
  现有入门校验，能力门控作为第二道，缺上限输入时退化为现有行为。
- 引擎新增角色查询与媒体空闲断言（无 compositor、无 TX 会话、无残留布局），
  供往返路径与运维自检使用；DRM plane 残留的最终确认仍在单板实测。

退出标准：重复切换无抖动；超能力 TX 参数被显式拒绝；空闲断言单测全绿。

验证：x86 跑 TX 会话单测（含能力门控用例）；RK3588 实测 input 进出与
资源释放。

## 6. 角色切换往返闭环

现状：`set_role("input")` 停 RX 侧并保留 TX 会话（重复切换不丢链），
`set_role("output")` 停 TX 数据面与会话，`tx_start` 在 input 角色下先清
RX  compositor 再建链，`clear` 与引擎停止覆盖其余 teardown 点。

剩余问题：往返路径缺少“起点—终点状态一致”的机器可判标准；残留布局、
残留会话、残留 TX 三者没有一句话能查完的接口。

修改方案：

- 以第 5 章的媒体空闲断言为往返判据：`output -> input -> output` 全程
  结束后断言空闲成立，任一残留即判失败。
- 不新增后台线程与定时器；往返驱动仍由调用方（平台 operation 或单板
  脚本）发起，引擎只保证每次切换的原子性与幂等性。

退出标准：往返脚本在单板连续执行无残留、无泄漏告警。

验证：x86 以会话与状态机单测覆盖 等价路径；RK3588 跑往返脚本并检查
plane 与会话计数。

## 7. 实施顺序与工作量

1. 轻量单元与纯函数（音频 owner、流校验、能力三件套、TX 能力门控）加
   单测——x86 可闭环。
2. 桥接层接线（prepare 裁剪校验、PTP/backend 复用、未命中静音）——x86
   协议单测回归。
3. 引擎侧幂等与断言（角色快速路径、空闲断言、lane 健康标记）——语法与
   协议单测回归，硬件行为留单板。
4. 单板验证（音频跟随、跨格接缝、能力比对、input 往返）——RK3588。

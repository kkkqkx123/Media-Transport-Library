# DVS 延期任务初步设计（下一阶段参考）

> 范围：前端缺口修复中明确延期的三项：网络真实应用、输入采集与发送编排、会话接入完整实现。

## 共同原则

- 按职责划分，不建替代模块。复用原模块并直接修改，不因好坏比较而另起模块。
- 显式失败优于掩盖问题。不用回退逻辑把失败藏成成功。
- 状态诚实。落库意图、引擎生效、系统执行三者区分表达。
- 安全默认。高副作用动作默认不执行，生产开启需显式操作并在隔离环境验证。
- 无历史包袱。存储形状可直接调整，不做旧数据兼容。

## 一、网络真实应用

目标：让网络配置的生效含义从意图落库推进到系统已切换，且失败可回滚。

非目标：本阶段不做多发行版网络管理抽象，不接管整机网络策略。

做法设想：

- 职责不变，仍由代理负责校验、快照、执行、回滚与上报。是否独立文件按职责决定，不单为拆分而拆分。
- 默认保持意图落库。真实执行只在隔离环境经显式确认后进行，请求需携带确认信息，避免误触开发机。
- 流程按校验、快照、执行、连通检查、失败回滚的顺序收敛。任一步失败即置失败并保留原因，不谎称已生效。
- 执行需设超时并捕获输出，避免阻塞代理主流程。系统执行结果决定配置状态，意图落库成功不等于系统成功。
- 回滚对象包括节点网络对象、节点地址与系统侧已变更项，回滚失败本身也要如实上报。

待定问题：目标底座的网络管理方式单一样式选型，隔离环境的连通检查标准，生产开启的操作入口。

验证设想：仅在隔离环境验证，覆盖静态切换成功、失败回滚、超时回滚，不在开发机验证。

## 二、输入采集与发送编排

目标：输入盒可被控制面配置采集与发送参数，状态可反映采集与发送健康度。当前媒体引擎为纯接收，此项是唯一涉及数据面扩展的延期项。

非目标：不把采集链另复制一份平行实现，不在输入与输出同时激活两套数据面。

做法设想：

- 角色互斥是简化依据。同一时刻节点只处于输入或输出其一，引擎按角色切换现行管线，而非并发双管线。
- 输入角色激活时停止接收合成器并启动采集与发送；输出角色回到空闲等待布局；清理操作停止现行管线并释放资源。
- 输入配置语义扩展为采集口、编码参数与发送目标三部分。现有白名单语义保留给接收准入，不混用于发送。
- 控制接口扩展放在现有配置与状态查询上，不另立协议。状态查询需能区分采集状态、编码状态、发送状态与错误原因。
- 复用采集链按职责取用采集、转换、编码、发送各环节能力，不整块搬运，不建平行副本。接收路径不受影响是硬约束。
- 能力上报需补充采集与发送相关能力，前端据此校验，避免无能力约束的配置下发。

待定问题：采集口与编码参数的最小规格，发送目标与传输参数的最小规格，状态字段的最小集合，单节点自环验证方式。

验证设想：需在编译服务器构建并在单板验证，覆盖输入角色激活出流、切回输出停止发送、清理后无残留、接收回归无退化。

## 三、会话接入完整实现

目标：先回答是否需要完整会话，再决定做多深。当前连通性探测保留，不承诺完整会话。

非目标：不引入与媒体控制耦合的会话协议，不在代理内做完整通信业务。

做法设想：

- 若平台无明确依赖，保持探测语义。启用需参数完整并通过可达性探测，失败明确置失败且不影响媒体。
- 若平台明确依赖，再补最小注册与保活。范围限于注册、保活与状态上报，不做呼叫与媒体协商。
- 状态机保持禁用、探测中、已连接、失败四态，失败保留原因并支持重试。
- 心跳可携带接入状态摘要，接入失败不污染媒体状态。

待定问题：平台是否真正依赖会话接入，若依赖则补齐最小契约后再设计。

验证设想：覆盖参数不全拒绝、不可达失败隔离、可达连接成功三态，不验证完整会话业务。

## 顺序与依赖

先定网络底座选型与隔离环境，再定采集发送最小规格，最后视平台契约决定会话接入深度。采集发送依赖单板与编译服务器，需单独排期，不与控制面小改同批实施。

## 风险提示

- 网络与重启类动作副作用大，任何真实执行必须在隔离环境先行验证。
- 采集发送扩展不得破坏接收路径，需以接收回归为门禁。
- 任何掩盖失败的回退都会在后续形成回归隐患，设计评审时重点检查失败路径是否显性。

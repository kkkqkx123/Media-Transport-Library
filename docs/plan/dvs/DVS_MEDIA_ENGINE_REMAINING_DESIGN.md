# dvs_media 剩余任务细化设计（下一阶段）

范围只覆盖媒体引擎侧 `ME-1 / ME-2 / ME-4 / ME-5 / ME-6 / ME-7 / ME-8`，以及 `ME-3` 的单板验证。平台业务规则、场景快照、底图、时钟资格、播放任务不在本文。
基线为当前工作树静态审计结论：通道代码已存在，缺的是配额实测、健康实测、原子切换、裁剪渲染、音频跟随与硬件验证。

总体原则：直接改原模块，不新增替代模块，不保留旧兼容路径；探测失败只降级上报，不中断进程；计数与状态只报实测或明确回显，不伪造；注释只写意图，不引用本文编号。

## 1 基线回顾

* 引擎中枢为 `engine_ctx`，拥有 MTL 句柄与至多一个 `rx_compositor`，布局变更当前为重建或几何快速路径。
* 布局暂存为 `layout_executor` 的 pending 影子，提交时应用音频路由并调用引擎应用函数。
* 准入为 `session_admit` 的白名单加 8 槽 LRU。
* 能力为 `capability` 的 DRM 与 V4L2 枚举加固定配额与未知时钟版本。
* 音频为 `audio_arbiter` 的 Master 音量，属主仅决定设备字符串，空属主静音。
* 查询为 `ipc_server` 经引擎钩子组装计数、lane 明细、PTP 与 TX 快照。
* 合成器为 `rx_compositor`，渲染为 `drm_renderer`，布局解析为 `rk3588_common/display_layout`。

## 2 ME-1 能力配额真实化

目标是能力 JSON 不再出现固定配额冒充实测。

* 解码路数：保留保守默认值与环境覆盖用于 bring-up，在此之上增加运行时可用数概念。可用数等于静态上限减去已准入会话数，静态上限取合成器 lane 上限与 DRM plane 数中的较小者。任何 MPP 创建失败只影响可用数，不改写静态上限。修改只在原 `capability` 探测与原 `session_admit` 快照取值处完成。
* 输入输出端口：保持现有 DRM connector 与 V4L2 扫描不动，只补一条规则。空数组为真实空，不回填种子；引擎不可达保留旧值，不覆盖为空。
* 时钟：单调模式直接报未知；外部或内置模式下，有 MTL 句柄且读取时间非零报同步，否则报未知。偏移量定义为 MTL 时间与系统 TAI 时钟的差值并换算为微秒，读不到时报零且状态为未知，不伪造同步。
* 后端：从收发端口名前缀推导，与 MTL 初始化的 PMD 映射共用同一映射关系。单双端口合并时以实际注册端口为准，无法识别报未知。
* 版本：MTL 版本只在引擎已初始化后刷新，未初始化保持未知。

## 3 ME-2 查询健康真实化

目标是查询返回值从布局回显变为运行实测。

* 会话数取合成器 lane 数，无合成器时取准入快照数。
* 解码数取运行中 lane 数，不再复用会话数。运行定义为 lane 线程存活且近期有 PTS 推进，超时无推进的 lane 标记未就绪但仍计入会话。
* 图层数取当前送显布局层数，无画面为零。
* lane 明细保持现有字段，语义收紧。就绪为运行且未超时，丢帧为 MTL 统计的丢弃加损坏加不完整之和，时间戳为最近接收 PTS。无合成器时返回准入快照且就绪为假，丢帧与时间戳为零。
* PTP 与 TX 快照保持现有钩子不动，只要求时钟语义与 ME-1 一致。

## 4 ME-4 与 ME-3 单节点验证

代码双模式已存在，剩余是硬件验证，不是重写。

* 静态模式用有效布局配置启动，要求单板出画并周期上报统计。
* 受控模式先空布局初始化 MTL，再经 IPC 下发布局，要求首次提交快速出画。
* 一路、两路、四路布局各做一次热更新，要求画面不中断于无关 lane。
* 输入角色拒绝布局、输出角色拒绝发流、非法白名单拒绝布局，三者需验证错误直达且不破坏当前画面。
* 以上用同一批长跑完成，不单独编译。

## 5 ME-5 帧边界原子切换

目标是热切无黑帧。当前重建必闪断，几何快速路径只覆盖位置变化。

* 准备阶段在后台预建影子合成器，完成组播加入、会话创建、首帧解码与 plane 预分配，但不送显。当前画面保持不变。预建失败直接报未就绪，不触碰运行实例。
* 提交阶段只切换 plane 属性。几何-only 变化继续走现有布局更新路径；源变化走影子交换路径，在一个 vsync 生成内提交全部 plane，等待翻转完成。
* 失败回滚保留旧合成器继续送显，并丢弃影子。成功后释放旧实例并更新计数与 lane 状态。
* 目标时间语义保留。有目标时间时在提交点等待目标时钟，到时再做 plane 切换；等待期间若运行实例消失则直接失败。
* 并发保护沿用现有提交串行器，不新增锁层级。同一时刻只允许一个重建或交换在途，第二个直接报忙碌可重试。
* 修改点限于原引擎应用函数、原布局暂存、原合成器创建与启停、原渲染布局更新，不新增合成器替代实现。

## 6 ME-6 运行期动态换源

目标是单路换源不闪断其它路，常驻订阅行为可预期。

* 换源判定以源标识加端口为准，分辨率与裁剪变化视为源变化。仅位置变化走快速路径，其它变化走影子交换路径。
* 先建后拆。影子预建成功前不释放旧源准入，不停止旧 lane。交换成功后释放已消失的源，保留持续存在的源的 LRU 热度。
* LRU 保持 8 槽不变。准入时钟只在准入时推进，查询不推进。清空画面释放全部准入，角色切换到输入时释放显示侧准入但不触碰发送侧状态。
* 白名单收紧仍为硬拒绝。任一源未过白名单则整个准备失败，不做部分上画。

## 7 ME-7 源裁剪渲染

目标是跨格窗口只显示对应源区域。字段、解析与比较已有，缺渲染使用。

* 布局解析保持不变，零宽高表示全帧。校验要求裁剪矩形落在解码帧内，否则整个布局非法。
* 送显层结构增加源矩形，与目标矩形并存。布局更新函数同时比对目标与源矩形，任一变化即视为布局变化。
* 渲染送显时按源矩形设置 plane 源参数，按目标矩形设置目标位置。合成器快速路径已比对源矩形，保持不变即可触发正确的重建或更新分支。
* 全帧为源矩形的退化情况，渲染行为与现状一致，不引入分支性能回归。
* 修改点限于原布局结构、原布局解析与校验、原渲染更新与送显、原帧描述中的内容尺寸，不新增渲染器替代实现。

## 8 ME-8 音频归属路由

目标是音频跟随指定窗口，静音与音量语义诚实。

* 属主语义从设备字符串改为窗口标识。空属主表示无音频，直接静音。窗口标识在提交时解析为对应 lane 的音频端口，找不到则失败，不 fallback 到主路。
* 音频订阅只跟随属主 lane。属主切换且其余布局不变时，只重建音频订阅，不重建视频合成器。视频布局变化时，音频随提交一起应用。
* 音量只作用于 Master，范围收敛到合理区间。无属主强制静音，有属主按给定值应用，应用失败只记日志并如实上报，不谎称已生效。
* 查询中的音频状态如实反映当前属主、订阅端口状态与音量，不投射未生效的 pending 值。

## 9 跨任务契约与错误语义

* IPC 不新增动词。准备失败返回参数错误并附原因，提交时引擎失败返回内部错误且状态机保持已准备，忙碌返回可重试忙碌，超时返回内部错误。
* 白名单、窗口形状、输出范围、角色约束的拒绝一律 loud fail，不静默接受。跨格窗口的前端翻译问题仍由代理拒绝，不在引擎侧兼容。
* 日志集中在准备失败、提交失败、渲染超时、音频应用失败四处，正常切换只保留一行摘要。

## 10 验证安排

为减少编译次数，x86 只做一次全量构建并运行全部单测，覆盖状态机、准入、端口映射、布局解析、白名单校验、音频参数收敛、IPC 信封。RK3588 单板按顺序一次跑通静态出画、受控提交、四路热更新、单路换源、裁剪生效、音频跟随、目标时间切换与失败回滚。平台两节点闭环依赖本文件 ME-5 完成后联调，不在引擎单内重复。

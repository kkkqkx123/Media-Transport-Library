# RK3588 6.1 SDK 的 AF_XDP/eBPF 内核使能移植（rk3588bsp）

分析对象：devs 编译服务器 `/data/kkkqkx/rk3588bsp`（RK3588 Linux 6.1.118 SDK，单提交快照，
remote `192.168.101.29:7990/scm/opk/rk3588-6.1-linux.git`，工作区原本干净）。
参照源：bingo `/home/bingo/rk3588_5.1_XDP`（5.10.226 SDK 上的 XDP 使能改动，未提交，见
`docs/os/RK3588_SDK_XDP_GIT_REPOS.md`）。配套阅读：`AF_XDP_EBPF.md`（§6 启用清单）、
`docs/env/RK3588_BOARD_ENV.md`（板载实测）。执行日期：2026-10-24。

## 0. 一句话结论

5.1 XDP 树的 5 处未提交改动**不能直接 apply** 到 6.1 树（路径 `kernel/`→`kernel-6.1/` 符号链接被
git 拒绝、defconfig/DTS 上下文完全不同、`envsetup.sh` 已不存在）。本次按"结构化移植"完成：
以 6.1 `rockchip_linux_defconfig` 为基座，把 5.1 `ztl_defconfig`（XDP 版）的符号差集经
**6.1 Kconfig 符号库逐一校验**后生成新的 `ztl_defconfig` + `ztl_rk3588.config`，并移植
`Config.in.kernel` 默认值与 DTS 的 i2c4 禁用。`make olddefconfig`（defconfig + 片段合并）实测通过，
XDP/BPF/BTF/HUGETLBFS 全部就位。已提交为 `98e7f9606`，patch 存档于
`patches/rk3588/0001-kernel-6.1-enable-af_xdp-ebpf-for-mtl.patch`。

## 2. 移植内容（devs 工作区，4 处）

| 文件 | 状态 | 内容 |
|---|---|---|
| `kernel-6.1/arch/arm64/configs/ztl_defconfig` | 新增（919 行） | 6.1 `rockchip_linux_defconfig` 为基座 + 5.1 ztl_defconfig(XDP 版) 符号差集（209 项，全部经 6.1 Kconfig 校验）+ BTF 专项 |
| `kernel-6.1/arch/arm64/configs/ztl_rk3588.config` | 新增（21 行） | 5.1 原样拷贝（含 `CONFIG_YT6801=y`）；仅移除 `MALI_CSF_SUPPORT`（bifrost 专属，6.1 基座为 VALHALL，见 §3） |
| `device/rockchip/common/configs/Config.in.kernel` | 修改 | 与 5.1 完全一致的 ztl 改法：`RK_KERNEL_CFG` 默认改 `ztl_defconfig`；`RK_KERNEL_CFG_FRAGMENTS` 增加 `ztl_rk3588.config`（rk3588 family） |
| `kernel-6.1/arch/arm64/boot/dts/rockchip/ztl-rk3588-cm.dts` | 修改 | 末尾追加 `&i2c4 { status = "disabled"; };`（与 5.1 patch 相同，属板级调试遗留，见 §5） |

**XDP 核心符号**（`AF_XDP_EBPF.md` §6 步骤 1 的 6.1 版答案）：`XDP_SOCKETS`、`XDP_SOCKETS_DIAG`、
`BPF_SYSCALL`、`BPF_JIT`、`BPF_JIT_ALWAYS_ON`、`BPF_UNPRIV_DEFAULT_OFF`、`BPF_STREAM_PARSER`、
`CGROUP_BPF`、`CGROUP_HUGETLB`、`HUGETLBFS`、`DEBUG_INFO` + `DEBUG_INFO_BTF`，另含 ztl 板级差集
（nftables/iptables 全家、wireguard/bonding/tun/veth、MD-RAID、CAN、`STMMAC_UIO` 等）。

**BTF 专项**（6.1 与 5.1 的关键差异）：6.1 基座没有 `CONFIG_DEBUG_INFO=y`，且带有
`CONFIG_DEBUG_INFO_REDUCED=y`——而 6.1 的 `DEBUG_INFO_BTF` 明确 `depends on !DEBUG_INFO_REDUCED`。
因此移植时显式补 `DEBUG_INFO=y`、`DEBUG_INFO_BTF=y` 并把 `DEBUG_INFO_REDUCED` 置为 not set。
**构建期需要 `pahole`（dwarves ≥1.21，若工具链默认 DWARF5）**；6.1 基座保留
`DEBUG_INFO_DWARF_TOOLCHAIN_DEFAULT`，实际 DWARF 版本随 SDK 交叉 gcc 而定。

## 3. 5.10 → 6.1 符号迁移的实测处理

生成脚本对 5.1 ztl_defconfig 的每个符号做了三类判定（完整清单见
`/data/kkkqkx/xdp_6.1_port_audit.patch` 生成记录与 devs `/tmp/port_report.txt`）：

- **保留并加入（209 项）**：6.1 Kconfig 存在的符号原值加入；ztl 与 6.1 基座取值一致的共享符号
  不产生覆盖（实测 0 冲突），SDK 版本自然演变的 3 项（`BT_HCIUART`、`SERIAL_8250_NR_UARTS`
  10→32、`SERIAL_8250_RUNTIME_UARTS` 10→15）按 6.1 基座取值。
- **6.1 已不存在，跳过（17 项）**：`RCU_FAST_NO_HZ`、`CPU_FREQ_TIMES`、`ANDROID`、
  `ROCKCHIP_EFUSE`/`OTP`（6.1 改 `NVMEM_ROCKCHIP_EFUSE/OTP`，基座已有）、`I2C_HID`（改
  `I2C_HID_OF`）、`NF_LOG_NETDEV`、`NFT_COUNTER`、`NF_FLOW_TABLE_IPV4/IPV6`、
  `NETFILTER_XT_MATCH_QUOTA2*`、`DMABUF_HEAPS_DEFERRED_FREE/PAGE_POOL`、`IOMMU_*` 等。
- **6.1 基座已废弃，跳过（10 项）**：`HZ_300`、`ARM_CPUIDLE`、`ZSMALLOC`、`SATA_AHCI_PLATFORM`、
  `MALI_BIFROST*`、`PM_DEVFREQ` 等；另有 `MALI_CSF_SUPPORT`（bifrost 专属）跳过——
  **6.1 BSP 的 Mali 走 `MALI_VALHALL` + `MALI_MIDGARD`，不掺 5.1 的 bifrost 配置**，
  以免与 MPP 用户态 ABI 错配。

olddefconfig 复验（`/data/kkkqkx/kern_val` 临时树，不污染 SDK 工作区）：合并
`ztl_rk3588.config` 后全部关键符号落定（见 §2），仅 4 项被 kconfig 静默丢弃且均无害：
`ARM64_MTE`/`ARM64_TLB_RANGE`（本就是默认关闭的冗余 "is not set" 行）、
`FRAMEBUFFER_CONSOLE*`（6.1 依赖 `CONFIG_FB`，RK3588 6.1 纯 DRM 无 fbdev 子系统，控制台走
DRM fbdev 仿真——5.1 的 fbcon 配置在 6.1 自动失效，属预期）。

## 4. 与板上运行环境的衔接（接 `AF_XDP_EBPF.md` §6 与 `RK3588_BOARD_ENV.md`）

内核的正式编译流程（`./build.sh kernel-6.1` 及配置链、主机依赖如 pahole）见
`../dev/compile/RK3588_6.1_KERNEL_BUILD.md`。

- **HUGETLBFS 首次可开**：板载 5.10 内核 `# CONFIG_HUGETLBFS is not set`（`sysctl
  vm.nr_hugepages` 无效）是 MTL 全部后端的第一阻塞项；6.1 defconfig 已含 `HUGETLBFS=y`，
  arm64 `select ARCH_SUPPORTS_HUGETLBFS` 满足依赖，olddefconfig 实测保留。
- **驱动侧缺口不变**：板上两口均为 Motorcomm **yt6801**（6.1 BSP 驱动位于
  `drivers/net/ethernet/yt6801`，`CONFIG_YT6801=y` 经基座与片段双重保证），仍**不支持 native
  XDP**——AF_XDP 只能 generic(SKB) 挂载 + copy UMEM；队列限速（`MT_RL_TYPE_XDP_QUEUE_SYSFS`）
  仍不可用（MTL 只对驱动名 `ice` 探测），pacing 继续用 TSC 软件方式。
- **eBPF 诊断工具（`tools/ebpf/`）仍需额外内核项**：`KPROBES` 在 6.1 该 BSP 默认关闭
  （olddefconfig 后 `=n`），5.1 XDP 树也未开。如需 `et`/`lcore_monitor`，在 defconfig 补
  `CONFIG_KPROBES=y`（`FTRACE`/`PERF_EVENTS` 默认已开）。
- **`BPFILTER=y`**：6.1 BSP 仍保留 `menuconfig BPFILTER`（net/bpfilter/），为与 5.1 XDP 树一致
  保留；无用例可删。

## 5. 未移植项及理由

| 5.1 XDP 树改动 | 处理 | 理由 |
|---|---|---|
| `kernel/tools/bpf/bpftool/Makefile` +1 行 `$(warning …)` | 不移植 | 交叉编译排查用的调试残留，非功能改动 |
| `device/rockchip/common/scripts/mk-updateimg.sh` +1 行 echo | 不移植 | 打包调试残留（该项其实可干净 apply，仍选择不带入） |
| `rockchip_rk3588_ztl_cm588_defconfig` +`RK_PACKAGE_FILE_CUSTOM=y` 及 untracked `package-file` | 不移植 | 自定义分区表打包，与 XDP 无关；6.1 版该文件仅 2 行（无 `RK_PARAMETER`），强行 apply 也会失败 |
| `envsetup.sh` 删除 | 不移植 | 6.1 树本无此文件 |
| DTS `&i2c4 disabled` | **已移植** | 与 5.1 工作区状态保持一致；属板级调试遗留，如 CM588 需要 i2c4 可随时去掉这一处 hunk |

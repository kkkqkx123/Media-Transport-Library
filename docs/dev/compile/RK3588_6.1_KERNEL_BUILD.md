# RK3588 6.1 SDK 内核正式编译指南（rk3588bsp / CM588）

分析对象：devs `/data/kkkqkx/rk3588bsp`（Rockchip rk3588-6.1 Linux SDK，内核 6.1.118，
git 单仓快照 + 我们的 AF_XDP/eBPF 使能提交 `98e7f9606`，见
`docs/analysis/RK3588_6.1_XDP_PORT.md`）。目标：把带 `ztl_defconfig`（XDP/BPF/BTF/HUGETLBFS
全开）的内核按 SDK 正规流程编出可烧录镜像。执行日期：2026-10-24，除内核配置生成外未做完整
内核编译（流程均从 SDK 脚本源码逐层核实）。

## 0. 一句话结论

```bash
cd /data/kkkqkx/rk3588bsp
./build.sh rockchip_rk3588_ztl_cm588_defconfig   # 选板（首次/切换时）
./build.sh kernel-6.1                            # 正式编译内核 -> kernel/boot.img -> output/firmware/
./build.sh firmware                              # 打包固件（含 boot.img 校验）
./build.sh updateimg                             # 生成 output/firmware/update.img（整包烧录）
```

配置链是两层的：SDK kconfig（`output/.config`，决定 `RK_KERNEL_CFG=ztl_defconfig` 与片段
`ztl_rk3588.config`）→ 内核 kconfig（`kernel-6.1/.config`，由 `make ztl_defconfig
rk3588.config rk3588_linux.config ztl_rk3588.config` 多目标合并生成）。该调用序已在 devs
实测复现，`XDP_SOCKETS/BPF_SYSCALL/BPF_JIT/DEBUG_INFO_BTF/HUGETLBFS` 全部落定。

## 1. 构建体系：两层 kconfig + 一个 build.sh

| 层 | 配置文件 | 入口 | 产物 |
|---|---|---|---|
| SDK 板级层 | `device/rockchip/.chips/rk3588/rockchip_rk3588_ztl_cm588_defconfig`（DTS/FIT/参数）→ `output/.config` | `./build.sh <defconfig>` → 根 `Makefile` 的 `%_defconfig` 规则（kconfig conf，Config.in 树） | `output/.config`、`output/defconfig` 软链 |
| 内核层 | `kernel-6.1/arch/arm64/configs/ztl_defconfig` + `ztl_rk3588.config` 片段（+自动发现的 `rk3588.config`/`rk3588_linux.config` 基础片段） | `device/rockchip/common/scripts/mk-kernel.sh` | `kernel-6.1/.config`、`Image`/`Image.lz4`、`rockchip/ztl-rk3588-cm.dtb`、`kernel/boot.img` |
| 打包层 | `device/rockchip/.chips/rk3588/boot.its`（FIT）、`parameter.txt` | `mk-kernel.sh` → `mk-fitimage.sh`/`scripts/mkimg`；`mk-firmware.sh` → `mk-updateimg.sh` | `output/firmware/boot.img`、`output/firmware/update.img` |

调用链（`./build.sh kernel-6.1`）：

```
build.sh (prepare_config: 校验/刷新 output/.config)
└─ device/rockchip/common/scripts/mk-kernel.sh
   ├─ do_make_kernel_config "ztl_defconfig" "ztl_rk3588.config"
   │   └─ make -C kernel -j$((nproc+1)) CROSS_COMPILE=aarch64-none-linux-gnu- ARCH=arm64 \
   │        ztl_defconfig rk3588.config rk3588_linux.config ztl_rk3588.config
   ├─ check-kernel.sh（ext4/USB gadget 等必要条件检查）
   ├─ make -C kernel ... ztl-rk3588-cm.img
   │   └─ arch/arm64/Makefile 的 %.img 规则：
   │        make rockchip/ztl-rk3588-cm.dtb Image.lz4 [modules]
   │        scripts/mkimg --dtb ztl-rk3588-cm.dtb
   │          ├─ resource_tool（内核构建期生成的主机工具）→ kernel/resource.img
   │          └─ scripts/mkbootimg（Python）→ 初步 boot.img
   ├─ RK_USE_FIT_IMG=y → mk-fitimage.sh：把 boot.its 里的 @KERNEL_IMG@/@KERNEL_DTB@/@RESOURCE_IMG@
   │   替换为实际路径，用 rkbin/tools/mkimage -E -p 0x800 打成 FIT 版 kernel/boot.img
   │   （覆盖 %.img 阶段的初步产物；RK_KERNEL_IMG=arch/arm64/boot/Image，未压缩）
   ├─ ln -rsf kernel/boot.img output/firmware/boot.img
   └─ check-kernel-dtb.sh / check-power-domain.sh
```

### 多目标配置合并机制（为什么一条 make 能同时吃 defconfig 和片段）

内核 `scripts/kconfig/Makefile` 的两条规则，按 make 目标后缀分流：

| 目标 | 规则 | 效果 |
|---|---|---|
| `ztl_defconfig` | `%_defconfig` | `conf --defconfig=arch/arm64/configs/ztl_defconfig`，**覆写** `.config` |
| `rk3588.config` / `rk3588_linux.config` / `ztl_rk3588.config` | `%.config` | `merge_config.sh -m .config <片段>` + `olddefconfig`，**增量合并** |

因此合并优先级（后者胜）：`ztl_defconfig` < `rk3588.config` < `rk3588_linux.config` <
`ztl_rk3588.config`。`rk3588.config`/`rk3588_linux.config` 是 SDK 按芯片名自动发现的"基础片段"
（前者设 MALI_VALHALL 等，后者设 BCMDHD），`ztl_rk3588.config` 是我们的板级片段（YT6801 等），
排在最后优先级最高。

## 2. 主机环境要求（devs 实测）

devs = Ubuntu 18.04.5 / x86_64。SDK 构建用**自带交叉工具链**（`prebuilts/gcc/linux-x86/aarch64/
gcc-arm-10.3-2021.07-x86_64-aarch64-none-linux-gnu`，gcc 10.3，由 `get_toolchain kernel arm64`
按 `aarch64-none-linux-gnu-` 前缀选中；`arm-gnu-toolchain-13.2` 只给 u-boot/ATF/TEE 用），
主机侧只需要构建内核的基础工具：

| 工具 | devs 现状 | 说明 |
|---|---|---|
| gcc/make（主机） | gcc 7.5、make 4.1 ✓ | 编 scripts/ 与主机工具 |
| flex / bison | 2.6.4 / 3.0.4 ✓ | kconfig 必需 |
| bc / dtc / lz4 | ✓（dtc 1.4.5、lz4 1.9.4） | 内核版本脚本、设备树、`Image.lz4` |
| python3 / ncurses | 3.6.9 / ✓ | kconfig、menuconfig；`scripts/mkbootimg` 是 Python 脚本 |
| **pahole（dwarves）** | **缺失，必须安装** | `CONFIG_DEBUG_INFO_BTF=y` 的构建期硬依赖；没有它 BTF 阶段直接报错退出。`sudo apt install dwarves`（devs 源候选 `1.21-0ubuntu1~18.04`）。本 SDK 交叉 gcc 10.3 默认 DWARF4，不触发 `DEBUG_INFO_DWARF5` 的 pahole≥1.21 门槛，任何 ≥1.16 的 pahole 均可 |
| mkimage | **主机不需要** | FIT 打包走 SDK 自带 `rkbin/tools/mkimage`（x86_64 静态二进制，已实测可运行）；`%.img` 步骤的 `scripts/mkbootimg` 是 Python 脚本。devs 主机虽无 `mkimage`/`u-boot-tools`，不影响 `./build.sh kernel-6.1` |
| swig | 缺失 | 内核构建不需要；全量构建（rootfs 周边）若报错再补 |

磁盘：`output/`（固件+update.img，数 GB 级）与内核构建中间体；devs `/data` 余量充足。
**编译不会污染 git 状态**：`output/`（顶层 .gitignore）、`kernel-6.1/.config`、`*.img`、`out/`、
`Image` 均被各级 `.gitignore` 覆盖（已用 `git check-ignore` 逐项验证）。

## 3. 正式编译命令

### 3.1 选择板级配置（首次或切换板子时）

```bash
./build.sh rockchip_rk3588_ztl_cm588_defconfig
```

等价于 `./build.sh rk3588:rockchip_rk3588_ztl_cm588_defconfig`。该命令（`mk-config.sh` 的
`switch_defconfig`）：把 `output/defconfig` 软链到该文件、把 `device/rockchip/.chip` 指回
`.chips/rk3588`、并在 SDK 根执行 `make rockchip_rk3588_ztl_cm588_defconfig` 生成
`output/.config`。之后每次 `./build.sh` 都会经 `prepare_config` 校验该链的有效性
（失效/过期会自动重生成）。

**首次构建必须先选板**：否则 `output/defconfig` 不存在，`prepare_config` 会走
`choose_defconfig` 交互式询问（脚本化环境会卡在 read 上）。

### 3.2 编译内核（日常迭代入口）

```bash
./build.sh kernel-6.1              # 正式编
./build.sh kernel-6.1:dry-run      # 只打印将执行的命令，不编译（审计/排错用）
```

`kernel` 是 `kernel-6.1` 的别名（`kernel_version()` 识别 `kernel-*` 目录）。等价手工命令
（调试时可直接跑，注意与 SDK 的 `-j` 和工具链保持一致）：

```bash
TC=prebuilts/gcc/linux-x86/aarch64/gcc-arm-10.3-2021.07-x86_64-aarch64-none-linux-gnu/bin/aarch64-none-linux-gnu-
make -C kernel-6.1 -j$(( $(nproc) + 1 )) CROSS_COMPILE=$TC ARCH=arm64 \
     ztl_defconfig rk3588.config rk3588_linux.config ztl_rk3588.config
make -C kernel-6.1 -j$(( $(nproc) + 1 )) CROSS_COMPILE=$TC ARCH=arm64 ztl-rk3588-cm.img
```

### 3.3 全量构建（出整包）

```bash
./build.sh            # 默认目标 all
```

顺序（`mk-all.sh`）：security keys → misc → **loader（u-boot）** → **kernel** → **rootfs**
（buildroot/debian/yocto，最耗时）→ security-ramboot → recovery → amp → firmware（打 update.img）。
只改内核时**不要**跑 all，用 §3.2 + §3.4。

### 3.4 只编内核模块（外挂到现有 rootfs）

```bash
./build.sh kernel-modules:/tmp/kmods     # 装到指定目录（默认 output/kernel-modules）
```

### 3.5 打包与烧录产物

```bash
./build.sh firmware      # 汇总/校验 output/firmware 下各镜像
./build.sh updateimg     # afptool+rkImageMaker 打 output/firmware/update.img
```

产物落点：`rockdev` 是指向 `output/firmware` 的软链。分区表用 `device/rockchip/.chips/rk3588/
parameter.txt`（**注意**：6.1 的 cm588 板级配置没有 `RK_PARAMETER`，即不用 5.1 树那份
`parameter-rk3588-ztl.txt`；5.1 的 `RK_PACKAGE_FILE_CUSTOM`/`package-file` 自定义分区也未移植，
如需自定义分区见 `docs/analysis/RK3588_6.1_XDP_PORT.md` §5）。

### 3.6 改内核配置的正规入口

```bash
./build.sh kernel-config          # = kconfig：menuconfig → savedefconfig 回写 arch/arm64/configs/ztl_defconfig
```

注意 `savedefconfig` 会把 `ztl_defconfig` **最小化**（只留非默认项，文件从 919 行缩到数百行）——
这是 SDK 管理 defconfig 的正常方式，但会让"基于 rockchip_linux_defconfig 全量基线"的审计视角
丢失，提交前用 `git diff` 确认变化符合预期。SDK 层的 `./build.sh menuconfig` / `savedefconfig`
改的是 `output/.config`（板级开关），不是内核配置，别混用。

## 4. 验证点（编译后必查）

```bash
# 1) 内核 .config 关键项（XDP/eBPF/大页/BTF）
grep -E "XDP_SOCKETS|BPF_SYSCALL|BPF_JIT|BPF_JIT_ALWAYS_ON|BPF_UNPRIV_DEFAULT_OFF|DEBUG_INFO_BTF|HUGETLBFS|CGROUP_BPF" \
     kernel-6.1/.config
# 2) 板级网卡驱动与构建告警
grep YT6801 kernel-6.1/.config          # CONFIG_YT6801=y
# 3) 产物存在性与格式
ls -la kernel-6.1/boot.img output/firmware/boot.img
file kernel-6.1/arch/arm64/boot/Image kernel-6.1/arch/arm64/boot/dts/rockchip/ztl-rk3588-cm.dtb
# 4) 板上（烧录后）确认内核能力
zcat /proc/config.gz | grep -E "XDP_SOCKETS|BPF_JIT|HUGETLBFS|DEBUG_INFO_BTF"   # 若开 IKCONFIG
ls /sys/kernel/btf/vmlinux            # BTF 生成成功
```

`docs/analysis/AF_XDP_EBPF.md` §6 的运行期清单（hugepages、MtlManager、端口名）在此之后执行；
板上 yt6801 仍只能 generic XDP + copy 模式，属运行期限制，与编译无关。

## 5. 已知坑

| 坑 | 现象 | 对策 |
|---|---|---|
| 主机无 pahole | `BTF: .tmp_vmlinux.btf: pahole (pahole) is not available`，链接阶段失败 | `apt install dwarves` 后再编 |
| `CONFIG_WERROR=y`（6.1 基座自带） | 任何新增代码的 warning 都会中断构建 | 用 SDK 钉的 gcc 10.3 交叉编，别用主机 gcc 直接编内核 |
| `kernel-config` 后 defconfig 最小化 | 919 行 → 数百行，diff 噪音大 | 属正常；提交前核对语义变化 |
| `kernel` 是软链 | 直接 `cd kernel` 会跳到 `kernel-6.1`；git 拒绝穿透软链打补丁 | 用 `git apply` 时写 `kernel-6.1/` 全路径 |
| FIT/压缩镜像细节 | `%.img` 固定产 `Image.lz4` + FIT boot.img（`RK_USE_FIT_IMG=y`、`boot.its`） | 无需干预；排查启动问题先确认 boot.img 内 FIT 含 dtb |
| 并行度 | SDK 用 `-j$((nproc+1))` | 内存 <16G 时自行调低 `-j` |
| 重编 | 增量异常时 | `./build.sh clean-kernel` 后重来；`cleanall` 会清 output/ 全部镜像 |

# 实施路线与验证计划

本文把需求和技术方案拆成可执行的阶段，给出每阶段的交付物、退出标准和验证方法。工期为相对估算，需结合团队规模与硬件到货时间调整。

## 1. 阶段划分

```text
P0 基座验证
  -> P1 媒体引擎 MVP
  -> P2 平台控制面
  -> P3 同帧与跨格
  -> P4 节点运维与设备管理
  -> P5 规模化与加固
```

P1 与 P2 可以并行，P3 依赖 P1 和 P2 的接口稳定。P4 可以与 P3 部分并行。

## 2. P0 基座验证

**目标**：证明 MTL 在 RK3588 和目标网络上可运行，采集、编码、传输、解码、显示、音频、PTP 全链路可用。

**范围**：

1. 在 RK3588 上编译 MTL、DPDK/AF_XDP、MtlManager、示例应用。
2. 跑通 `app/rk3588_end2end both` 单板回环。
3. 跑通 `app/rk3588_mp4_dist` 单板和双机链路。
4. 配置 linuxptp，验证 PTP 同步状态和偏差。
5. 测量端到端时延、CPU、内存、温度和丢帧。
6. 验证组播加入/退出和 IGMP snooping。
7. 验证 MPP 并发解码路数、DRM plane 数量、RGA 缩放质量。

**交付物**：

- 可复现的节点镜像和构建脚本。
- 基座验证报告：版本、配置、拓扑、指标、问题清单。
- 硬件能力实测表，回填 `05-tech-links/hardware-capability-matrix.md`。
- 两节点最小演示：一路输入到一路输出。

**退出标准**：

- 1080p60 单路端到端稳定运行 30 分钟，无持续丢帧。
- PTP 偏差在目标阈值内，断网后能恢复。
- 组播两节点同时接收正常。
- 媒体引擎进程连续运行 24 小时不崩溃。

**建议工期**：2–3 周（依赖硬件到货）。

## 3. P1 媒体引擎 MVP

**目标**：把参考应用重构成可配置、可控制的节点媒体引擎，支持单节点多窗口和基础音频。

**范围**：

1. 抽出公共库：MPP、RGA、DRM、ALSA、PTP、ring buffer、slab pool、display layout。
2. 输入盒：V4L2 采集、编码参数配置、ST22 TX、ST30 TX、组播地址配置。
3. 输出盒：多路 ST22 RX、MPP 解码、播放缓冲、DRM 多 plane、RGA 裁剪缩放。
4. 本地布局执行器：接受 JSON 布局片段，应用到 DRM。
5. 音频：选择一路音频送到 ALSA，音量增益。
6. IPC：Unix socket 协议，支持 configure/prepare/commit/query。
7. 状态与统计：会话状态、解码状态、显示状态、PTP、MTL 统计。
8. 能力上报：端口、分辨率、编解码、解码路数、图层数。

**交付物**：

- `dvs-media` 可执行文件和配置说明。
- IPC 协议文档和 mock 客户端。
- 单节点 4 窗口演示。
- 单元测试：布局解析、坐标拆分、缓冲、状态机。

**退出标准**：

- 单节点 4 路 1080p60 同时显示，窗口可移动、缩放、调整层序。
- 音频跟随指定窗口，静音和音量生效。
- 媒体引擎重启后能恢复最后布局。
- 进程异常退出后由 systemd 拉起，30 秒内恢复出画。

**建议工期**：4–6 周。

## 4. P2 平台控制面

**目标**：完成分组、拼墙、设置、白名单、绑定、场景快照和 operation 框架，Web 后台可用。

**范围**：

1. 数据模型：`dvs_group`、`dvs_wall`、`dvs_scene`、`dvs_binding`、`dvs_whitelist`、`dvs_operation`。
2. REST API：按 `05-tech-links/apis.md` 实现 0001–0007。
3. revision 与幂等：写请求带 `Idempotency-Key`，更新带 revision。
4. 场景快照：窗口集合、音量、布局模式、未保存改动比较。
5. 节点注册与心跳：在线状态、能力快照。
6. 布局计算：整墙坐标、节点片段、跨格拆分。
7. Web 页面：分组列表、拼墙列表、设置 5 Tab、画面页、场景区。
8. 节点网关：WS 长连接、下发、回执、重连。

**交付物**：

- 平台服务、数据库迁移脚本、API 文档。
- 前端页面和 mock 回归。
- 两节点端到端演示：建组、建墙、绑定、加白名单、开窗、保存场景。

**退出标准**：

- 两节点 2×1 墙完整走通 FLOW-01。
- 场景保存、切换、清屏符合 REQ-0005/0006/0007 的 P0 规则。
- 非法参数、冲突绑定、越权操作返回统一错误码。
- API P95 ≤ 300 ms（128 节点模拟）。

**建议工期**：4–6 周。

## 5. P3 同帧与跨格

**目标**：实现跨节点 prepare/commit、统一 `apply_at`、跨格窗口、回滚和时钟资格。

**范围**：

1. 全局帧号和 epoch 管理。
2. prepare 屏障、commit 广播、回执聚合。
3. 节点影子布局、原子提交、rollback。
4. 跨格窗口拆分和接缝校准。
5. 时钟资格判定和 blocked_offline。
6. 预订阅和关键帧等待。
7. 切换失败的可视化：失败节点、阶段、重试入口。
8. 1000 次切换稳定性测试。

**交付物**：

- 同帧切换实现和测试报告。
- 2×2 墙跨格演示。
- 时钟拓扑和 PTP 配置手册。
- 失败注入记录。

**退出标准**：

- 2×2 墙 1000 次场景切换，无可见撕裂，平台记录的偏差 ≤ 1 帧。
- 任一节点离线时整墙阻止，画面不变。
- 提交后单节点失败能回滚到原布局，页面不更新当前场景。
- 跨格窗口边缘无明显接缝，误差 ≤ 1 像素。

**建议工期**：4–6 周。

## 6. P4 节点运维与设备管理

**目标**：完成节点本机后台、注册、网络、SIP、升级、退役和播放任务。

**范围**：

1. 节点本机页：登录、改密、角色、输入口、输出参数、网络、注册、SIP、本机信息、运维。
2. 角色切换作业：影响检查、平台清理、重启、注册验证、失败回退。
3. 网络配置：DHCP/静态、断连回滚。
4. 自动/手动注册、心跳、墓碑。
5. 固件升级：包校验、A/B 分区、进度、回滚。
6. 设备管理页面：列表、别名、退役、批量升级。
7. 播放任务：状态机、创建、检查、执行、结束、记录。
8. 本机物理复位键和默认密码恢复。

**交付物**：

- 节点代理和本机页。
- 升级包格式和签名工具。
- 设备管理和播放任务页面。
- 运维手册。

**退出标准**：

- 裸盒 3 分钟内配置成输出盒并注册成功。
- 角色切换在平台不可达时只登记意图，不重启。
- 升级失败后节点仍以旧版本启动。
- 播放任务八态流转符合 REQ-0011。
- 退役后 30 天内同 SN 注册被墓碑拦截。

**建议工期**：4–5 周。

## 7. P5 规模化与加固

**目标**：满足容量、连续运行、安全和可运维要求。

**范围**：

1. 128 节点模拟器：注册、心跳、operation 聚合。
2. 64 墙、单墙 64 窗口的布局计算压测。
3. 4×4 实际节点墙测试。
4. 24 小时连续运行和温升测试。
5. 故障注入：断网、断电、PTP 失锁、磁盘满、坏包、旧 revision。
6. 安全加固：TLS、证书轮换、登录限速、固件签名。
7. 监控与告警：节点离线、流中断、解码失败、时钟异常、磁盘和温度。
8. 性能调优：线程绑核、hugepage、AF_XDP、RGA 批处理。

**交付物**：

- 压测报告和容量结论。
- 故障注入报告。
- 安全评审记录。
- 运维监控面板和告警规则。

**退出标准**：

- 128 节点模拟下 API P95 ≤ 300 ms，P99 ≤ 800 ms。
- 24 小时无服务崩溃、节点异常重启和持续丢帧。
- 故障注入后系统能恢复，画面不黑屏。
- 安全扫描无高危问题。

**建议工期**：4 周。

### 9.4 故障注入

| 故障 | 期望 |
| --- | --- |
| 杀节点代理 | 媒体继续出画，代理重启后恢复状态 |
| 杀媒体引擎 | systemd 拉起，30 秒内恢复最后布局 |

| 并发重复请求 | 幂等返回首次结果 |

## 11. 风险登记

| ID | 风险 | 概率 | 影响 | 缓解 |
| --- | --- | --- | --- | --- |
| R1 | 千兆带宽不足或画质不达标 | 高 | 高 | 先做码流实测；必要时升级 2.5G/10G 或降低路数 |
| R2 | H.264 GOP 导致切换超过 1 s | 高 | 高 | 短 GOP、常驻订阅、全 intra 可选 |
| R3 | 跨独立显示器同帧无法证明 | 中 | 高 | PTP + 帧标记实测；必要时降级为“近似同帧”并调整验收 |
| R4 | 单节点 DRM plane 不足 | 中 | 中 | GPU/RGA 合成兜底；限制单节点窗口数 |
| R5 | MPP 并发解码和温升受限 | 中 | 中 | 实测解码路数；散热设计；动态淘汰 |
| R6 | ARM 只能软件 pacing | 高 | 中 | 闭环局域网可接受；对接广播设备时评估 E810/TSN |
| R7 | MTL 参考应用未产品化 | 高 | 中 | 抽公共库、补测试、固定上游版本 |
| R8 | AF_XDP/DPDK 权限与 hugepage 配置复杂 | 中 | 中 | 节点镜像预配置；systemd capability |
| R9 | H.264 in ST2110-22 与第三方设备互通性 | 中 | 低 | 内部闭环使用；对外互通时用标准编解码 |
| R10 | 固件升级失败变砖 | 中 | 高 | A/B 分区、签名、断电测试 |
| R11 | 节点本机页被未授权访问 | 中 | 中 | HTTPS、强密码、限速、网络隔离 |
| R12 | 平台与节点状态不一致 | 中 | 中 | revision + 回执 + 对账任务 |
| R13 | 硬件能力与文档不符 | 高 | 高 | 节点能力回读，平台不硬编码 |
| R14 | 多墙共享输入时组播地址冲突 | 低 | 中 | 地址池、保存校验、冲突检测 |

## 13. 启动清单

P0 第一周建议按以下顺序执行：

1. 在 RK3588 上编译 MTL，跑通 `./build.sh`。
2. 配置 hugepage、AF_XDP、MtlManager，跑通 `RxTxApp` 单机回环。
3. 跑通 `rk3588_end2end both`，记录时延和资源。
4. 配置两台机器 PTP，跑通 `rk3588_mp4_dist` 双机。
5. 用 Wireshark 抓包确认 ST2110-22/30 和组播。
6. 用 `v4l2-ctl`、`modetest`、`aplay` 分别验证采集、显示、音频。
7. 输出基座验证报告，确认 R1/R2/R3/R5/R6 的实际边界。
8. 根据实测结果回写本文和 `05-tech-links/hardware-capability-matrix.md`。

## 14. 完成定义

单条 REQ 完成需要同时满足：

- 功能符合 REQ 的 P0 规则和验收标准。
- 接口符合 API 契约，错误码完整。
- 单元和集成测试通过。
- 关键路径有日志、指标和审计。
- 故障场景有明确处理和验证记录。
- 文档状态由责任人确认后流转，本文不代替签字。

# DVS 与 RK3588 剩余任务方向

## 结论

代码静态审计表明，既有计划文档中部分缺口状态已过时。平台文档增删改查的形状校验、引用检查与资源占用保护，通道双模校验对称、上行回执回退、连接注册与发送原子化，代理传输状态保护与单调时钟超时，多数已在当前工作树落地。剩余任务按是否需要硬件与编译服务器分为两类，本次只做无需硬件、无需本地编译的代码项，其余明确延期。

## 本次做的代码项

* 跨编译显式头文件。部分采集编码与接收渲染源文件使用布尔类型但未显式包含标准布尔头文件，原生编译靠间接包含通过，交叉编译失败。本次逐文件补齐，不改任何逻辑。
* 平台到代理配置下发的允许键收敛到契约一处。契约校验、平台扇出过滤、代理落盘三处各写一次允许键集合，新增键容易只改一处。本次把允许集合收敛为契约内的单一判定函数，三处只读判定结果，不再各自硬编码键名。校验行为不变，非法键仍被拒绝。

## 明确延期的任务

* 内核与驱动改动、显示器与片源相关的端到端验证、双机时钟同步、长稳运行，全部需要板端硬件与编译服务器，不在本次本地改动范围内。
* 媒体数据面能力配额真实化、健康计数真实化、帧边界原子切换、源裁剪渲染、音频归属路由，需要 Rockchip 相关硬件在单板实测，不在本次改动范围内。
* 底图拆分下发、图像调节逐项结论、播放任务联动、容量压测，需要端到端联调，不在本次改动范围内。

## 后续顺序

* 先合入本次两项小改动，保持行为不变。
* 再由编译服务器完成交叉编译验证，确认头文件补齐生效。
* 硬件相关的验证与媒体收尾待板端条件具备后另行推进，不与本次混批。

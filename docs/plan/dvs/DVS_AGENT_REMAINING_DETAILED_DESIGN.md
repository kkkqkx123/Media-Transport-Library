# 节点代理剩余任务细化设计（AG-2 ~ AG-7 与本机前端缺口）

> 范围只覆盖 `app/dvs_agent`。媒体引擎、平台服务、构建验证见真相源
> `docs/plan/dvs/BACKEND_STATUS_AND_REMAINING_TASKS.md` 第 2 章，本文件是其中
> 代理侧七行剩余描述的展开，不改状态结论。
> 基线：六 scope 状态机、注册/心跳、本地 HTTP、维护操作、媒体 IPC 转发（命令/查询双通道、
> 版本门禁、revision 守卫、后台输出翻转、输入同步透传引擎错误）均已实现；
> 缺的是角色联动的平台可见性、热插拔联动、网络真实执行的隔离验证形态、
> 日志/来源/审计三处桩接口与播放投影/指标回填。
> 写作约束：自然语言为主，不贴完整代码；只改原模块，不起替代模块，不留兼容双轨；
> 注释只描述意图，不引用文档编号。

## 1 现状与设计原则

代理今天是一个“能存意图、能转引擎、能报心跳”的单节点控制面，
但三类语义是混的：平台下发的角色与本机保存的角色走两条 pending 路径，
输出口能力只在启动与请求时合并、无热插拔联动，
网络 applied 表示意图落库而非系统已切换但前端易误读，
来源/日志/审计三处读接口返回空桩，
本机信息页的指标与播放投影依赖前端本地拼凑而非后端回填。

本设计遵循四条原则：

- 诚实状态：已落库、意图已存、引擎已生效、系统已执行四者永不混用同一状态词。
- 平台只做规则与扇出，节点只做本机真相：角色切换的清理联动靠平台可见的
  pending 意图触发，节点不替平台删绑定/白名单。
- 高副作用默认安全：网络切换、重启、固件切换保持显式环境门控，
  响应体如实标注是否受控，不反转门控为默认执行。
- 持久化只增字段不改形状：新增语义用新字段承载，旧库读不到按缺省处理；
  读接口从现有引擎查询与本地状态合成真相，不引入新的进程间传输机制。

## 2 AG-2 角色切换与平台清理联动

### 2.1 现状

保存路径三处分叉：本机 HTTP scope 入口写 pendingRole 并延迟到重启激活，
平台配置同步入口写 pendingRole，平台 WS 下行入口只调期望值存储而不写
pendingRole。心跳与注册负载只带当前角色，不带待切换意图，
平台侧看不到谁在等重启，也就无法在切换前清理该节点的墙绑定与白名单。

### 2.2 设计

落点全部在原文件内，不新增模块：

- 收敛一处角色意图函数，由三处入口共用：参数为目标角色与来源标记；
  行为是期望值存储加待激活角色置位或清除（目标等于当前角色则清除待激活），
  非法取值直接拒绝并记失败原因。重启路径的提升与媒体清理逻辑不动。
- 待激活角色进入平台可见面：注册负载与心跳负载在现有角色字段旁新增
  待激活角色字段，无待激活时为空；平台据此在切换生效前完成绑定与白名单清理。
- 平台不可达时的语义冻结为本地意图：待激活在本地持久化， survives 重启前的
  多次保存（后保存覆盖先保存），重启即提升；不可达不自动回滚，
  撤销只能由本机或平台显式下发原角色覆盖。

错误表达沿用现有信封：非法角色为参数错误，转发故事沿用现有 pending 轮询。

退出标准：三处入口保存后待激活一致可读；心跳与注册携带待激活；
本机重启提升并按新角色清理对侧媒体；平台不可达时意图不丢不误触发。

验证：单元覆盖期望值存储与待激活置位/清除矩阵；
单机覆盖本机保存、平台同步、WS 下行三路一致性与重启提升。

## 3 AG-3 输出热插拔与 EDID 联动

### 3.1 现状

输出保存按缓存能力做上限校验，超限拒绝；保存后走 pending 加后台按引擎结果翻转。
能力合并发生在启动与每次能力请求时，引擎不可达保留旧值、引擎明确空数组如实传播。
缺的是热插拔联动：线缆插拔或 EDID 变化后缓存能力不变，
已保存的输出可能悄然越界，前端继续显示已生效。

### 3.2 设计

落点在代理主循环内的轻量轮询，不新增守护进程形态：

- 后台按固定间隔（十秒量级）经查询通道拉一次引擎能力，
  与缓存做端口集合与单口上限比较；无变化只刷新新鲜度时间戳。
- 变化时如实合并新能力并做一次输出重校验：当前已保存输出口消失或越界，
  则将输出 scope 置失败并写明热插拔变化原因，同时在节点异常字段记录一次；
  仍在界内则保持已生效，不打扰画面。
- 强推与热插拔两种模式语义不变：强推按保存值要求引擎输出，
  热插拔允许引擎按 EDID 自适应；轮询只做越界失败显性化，不自动改写用户保存值。

退出标准：拔线或换显示器后能力新鲜度更新，越界输出在轮询周期内转为失败并带原因；
界内输出不受打扰；引擎不可达时保留旧值不误报。

验证：单机拔插或以环境变量模拟能力变化，观察能力时间戳、输出状态与异常字段；
无显示器环境下验证不可达保留旧值。

## 4 AG-4 网络系统应用隔离验证

### 4.1 现状

校验、快照、回滚、门控、执行结果上报、注册模式均已实现；
系统应用函数经显式环境加确认加操作标识三重门控后才执行，
否则只落意图并如实返回未切换。缺的是隔离验证形态：
执行日志只落盘不对外可读，意图与执行在前端易混，真实切换从未在隔离环境走完。

### 4.2 设计

不拆分新模块，不新增网络后端实现：

- 语义冻结：已应用表示意图已落库，系统已执行另由执行标记字段表达；
  两类文案在响应与前端保持区分，不合并。
- 执行可观测：节点对象已有的系统执行记录（是否执行、方式、时间、错误、是否回滚）
  保持随本机信息返回；本地日志读接口新增网络执行日志尾部，
  内容为最近一次执行的快照摘要与连通检查结论，失败时含回滚结论。
- 隔离验证步骤固化为文档：隔离网段、显式门控开启、确认位与操作标识齐备、
  执行后连通检查通过、失败回滚后旧地址可达；开发机默认永不开启门控。

退出标准：未开门控调用永不触碰系统网络且响应如实；
开门控调用在隔离环境走完写文件、重载、连通检查、失败回滚全链路；
日志尾部可读，意图与执行不再混淆。

验证：单元覆盖解析、掩码、网卡名、门控矩阵与渲染；
隔离环境覆盖成功切换与注入失败回滚，开发机覆盖默认门控关闭。

## 5 AG-5 会话接入（SIP）范围决策

### 5.1 现状

关闭直接落库，启用做参数校验加 TCP 可达性探测，失败明确置失败且不影响媒体。
完整会话需要 SIP 注册机与媒体面耦合，本轮无规格。

### 5.2 设计

本轮不做完整会话，只做诚实化：

- 接入对象新增模式字段固定为连通性探测，前端与文档明确标注，
  不承诺注册会话、订阅或呼叫能力。
- 探测中状态先发布再覆盖，调用方轮询可见；不可达置失败并带原因，已连接为探测成功。
- 完整会话延期项记为：注册保活、鉴权、掉线重连、与媒体面的联动策略，需另立规格。

退出标准：启用失败时状态为失败且原因明确；成功时标注为探测成功而非会话已建；
媒体状态永不受探测影响。

## 6 AG-6 固件 A/B 真实切换

### 6.1 现状

上传落盘、摘要校验、分版本暂存、失败保留旧版、真实切换保持门控均已实现；
门控关闭时报告已暂存待切换，开启时才 bump 版本号。

### 6.2 设计

保持门控默认关闭，只补全可观测与回滚诚实性：

- 升级记录落节点对象：文件名、版本、摘要、状态（已暂存或已应用）、时间；
  本机信息页直接可读，不依赖前端本地记忆。
- 校验失败保留旧版并允许重试的语义不变；切换失败路径明确为保留旧版，
  不写新版本号。
- 真实 A/B 分区切换（bootloader 槽位翻转、掉电保护）仍保持门控，
  需在单板隔离环境另行联调，本轮不落地分区操作。

退出标准：上传损坏包被拒绝且旧版不变；暂存与应用两种响应可区分；
升级记录可读；开发机调用永不误切换。

## 7 AG-7 本机媒体状态/能力/日志收尾

### 7.1 现状

启动拉取、按需刷新、过期标记、空数组透传、lane 与 TX 与 PTP 透传、心跳摘要
（媒体计数、lane 就绪摘要、TX 摘要、SIP 摘要、资源）均已实现。
三处读接口仍为桩：来源返回空对象，日志返回空数组，审计返回空页。
本机信息的指标与播放投影未回填：容量接口可算但不进节点对象，
当前播放永为空，心跳的媒体摘要不落库。

### 7.2 设计

全部在原 HTTP 层合成真相，不新增 IPC 动词：

- 来源接口：以引擎状态查询的 lane 数组为真相，叠加本机输入配置的端口与白名单，
  返回 lane 明细与输入意图；引擎不可达时返回其错误信封，不伪造空闲。
- 日志接口：返回代理侧有界日志环尾部（配置保存/生效/失败、网络执行、重启/升级、
  引擎链路翻转、版本门禁触发），叠加引擎链路状态与能力新鲜度；
  条目带时间、范围、动作、结论，不存全量历史。
- 审计接口：返回同一日志环的分页视图，支持页码与页大小参数，
  总数真实，空时返回空页而非错误。
- 播放投影：媒体状态查询成功时按 lane 是否就绪折叠为当前播放
 （有就绪 lane 为播放中，否则无播放），写回节点当前播放并带更新时间；
  本机信息与心跳直接读该字段，前端不再本地推测。
- 指标回填：本机信息读时合并实时容量（CPU、内存、负载、运行时间）与引擎链路，
  只做读时合并，不污染持久化快照；温度读不到时如实为空。

退出标准：三处桩接口返回真实合成数据；有播放时本机信息显示播放中，
无播放时显示无播放；指标与能力新鲜度可读；引擎不可达时各接口如实报错而非空闲。

验证：单元覆盖分页与投影折叠；单机覆盖有流/无流/引擎不可达三态；
前端覆盖无能力上报时的禁用与空安全。

## 8 实施顺序与回归边界

顺序：先做角色收敛与播放投影/指标回填（纯本机，无副作用），
再做热插拔轮询与来源/日志/审计合成（只读引擎，不改画面），
最后做网络日志可读、固件记录、SIP 模式标注（文案与记录层）。
SIP 完整会话与固件真实分区切换明确延期，不与本轮同窗。

回归边界：配置状态机、双通道 IPC、版本门禁、revision 守卫、意图门控、
白名单逐项校验、输出上限校验、墓碑语义均不动；
所有改动直接修改原模块，不创建替代模块或兼容层。

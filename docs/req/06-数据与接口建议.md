# 数据模型与接口建议

本文在 `05-tech-links/databases.md` 和 `05-tech-links/apis.md` 的基础上，补充媒体面所需的数据字段、节点协议和 operation 消息结构。字段命名以现有草案为准，新增部分需开发评审。

## 1. 数据模型补充

### 1.1 dvs_wall

新增整墙像素坐标和格位矩阵：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `wall_px_w` | int | 整墙像素宽 |
| `wall_px_h` | int | 整墙像素高 |
| `cell_grid` | json | 每格 `{r,c,x,y,w,h}`，建墙时固化 |
| `layout_mode` | enum | free / fixed |
| `snapshot_version` | int | 场景快照结构版本 |

`cell_grid` 示例：

```json
[
  {"r":0,"c":0,"x":0,"y":0,"w":1920,"h":1080},
  {"r":0,"c":1,"x":1920,"y":0,"w":1920,"h":1080},
  {"r":1,"c":0,"x":0,"y":1080,"w":1920,"h":1080},
  {"r":1,"c":1,"x":1920,"y":1080,"w":1920,"h":1080}
]
```

### 1.2 dvs_whitelist

新增媒体参数：

| 字段 | 说明 |
| --- | --- |
| `mcast_ip` | 组播地址，单播时为空 |
| `mcast_port` | 视频端口 |
| `audio_port` | 音频端口 |
| `source_ip` | 输入盒源地址，用于 SSM 过滤 |
| `codec` | h264 / hevc / jpegxs / raw |
| `width`、`height`、`fps` | 编码参数 |
| `bitrate_kbps` | 目标码率 |
| `gop_ms` | 关键帧间隔 |
| `status` | active / pending / conflict |

同一 `mcast_ip:mcast_port` 在系统内唯一，保存时校验冲突。

### 1.3 dvs_binding

补充媒体下发状态：

| 字段 | 说明 |
| --- | --- |
| `status` | active / pending_offline / failed |
| `desired_revision` | 期望绑定 revision |
| `applied_revision` | 节点已生效 revision |
| `output_port_id` | 节点输出口标识 |
| `node_origin_x`、`node_origin_y` | 节点本地画布原点 |
| `node_canvas_w`、`node_canvas_h` | 节点本地画布尺寸 |

`node_origin` 和 `canvas` 由绑定格位包围盒计算，冗余存储便于排查。

### 1.4 dvs_scene

快照结构版本化：

```json
{
  "snapshotVersion": 1,
  "volume": 80,
  "layoutMode": "free",
  "baseImageRevision": 7,
  "windows": [
    {
      "windowId": "w1",
      "signalId": "in01-hdmi1",
      "x": 0, "y": 0, "w": 3840, "h": 2160,
      "z": 10,
      "muted": false,
      "fit": "stretch",
      "minSize": "cell/16"
    }
  ]
}
```

`fit` 固定为 `stretch`（本期不做裁切）。`minSize` 用于校验，运行时以平台计算为准。

### 1.5 dvs_operation

补充：

| 字段 | 说明 |
| --- | --- |
| `layout_hash` | 布局片段哈希，用于幂等和一致性校验 |
| `guard_ms` | 提交保护带 |
| `apply_at` | 统一生效时刻，TAI |
| `epoch_tai_ns` | 会话帧纪元 |
| `fps` | 输出帧率 |
| `rollback_revision` | 回滚目标 |
| `result_reason` | 失败原因 |

### 1.6 dvs_operation_node

补充：

| 字段 | 说明 |
| --- | --- |
| `prepared_at` | ready 时间 |
| `committed_at` | 实际提交时间 |
| `frame_index` | 目标帧号 |
| `clock_offset_us` | 提交时时钟偏差 |
| `decode_ready_json` | 每个信号的解码就绪状态 |
| `late` | 是否错过提交窗口 |
| `applied_layout_hash` | 节点实际应用的布局哈希 |

### 1.7 dvs_capability

建议独立表或 `dvs_node.capability` JSON：

| 字段 | 说明 |
| --- | --- |
| `node_id` | 节点 |
| `report_version` | 能力结构版本 |
| `input_ports` | JSON 数组 |
| `output_ports` | JSON 数组 |
| `codecs_encode` | 数组 |
| `codecs_decode` | 数组 |
| `max_decode_sessions` | 最大并发解码 |
| `max_layers` | 最大图层 |
| `ptp` | JSON：supported/hwTimestamp/domain |
| `mtl` | JSON：version/backend |
| `firmware` | 版本 |
| `reported_at` | 上报时间 |

### 1.8 dvs_media_session（可选）

运行态投影，便于排障：

| 字段 | 说明 |
| --- | --- |
| `node_id`、`wall_id`、`signal_id` | 关联 |
| `direction` | tx / rx |
| `state` | idle / joining / receiving / decoding / failed |
| `mcast_ip`、`port` | 地址 |
| `last_frame_at` | 最后一帧时间 |
| `decode_errors` | 计数 |
| `bitrate_kbps` | 实测码率 |
| `updated_at` | 更新时间 |

该表可以只保留在节点侧，平台按需拉取，避免高频写入数据库。

### 1.9 dvs_playback_task

补充：

| 字段 | 说明 |
| --- | --- |
| `operation_id` | 关联的场景切换 operation |
| `target_node_id` | 目标输出盒 |
| `current_playback_revision` | 节点投影 revision |
| `error_stage` | check / execute / play |
| `ended_reason` | 结束原因 |

### 1.10 dvs_audit_event

建议增加媒体相关事件类型：

```text
MEDIA_PREPARE_START / MEDIA_PREPARE_READY / MEDIA_COMMIT / MEDIA_APPLIED
MEDIA_ROLLBACK / MEDIA_SESSION_JOIN / MEDIA_SESSION_LEAVE
CLOCK_UNSYNCED / DECODE_FAILED / STREAM_LOST / STREAM_RECOVERED
```

## 2. 平台到节点协议

### 2.1 传输

建议使用 WSS 或 gRPC over TLS，Node 主动连接平台，便于穿透 NAT。消息带：

```json
{
  "protocolVersion": 1,
  "messageId": "msg_01H...",
  "nodeId": "node_1",
  "timestampTaiNs": 1700000000000000000,
  "type": "media.prepare",
  "payload": {}
}
```

节点回执带同一个 `messageId` 和 `operationId`。重复消息按 `messageId` 幂等。

### 2.2 注册

```json
{
  "type": "node.register",
  "payload": {
    "sn": "RK3588-0001",
    "mac": "02:00:00:00:00:01",
    "model": "DVS-OUT-1",
    "firmware": "1.0.0",
    "role": "output",
    "capability": { "...": "见 1.7" },
    "network": {"ip": "192.168.10.21", "gateway": "192.168.10.1"},
    "ptp": {"state": "synced", "offsetUs": 120}
  }
}
```

平台返回：

```json
{
  "type": "node.register.ack",
  "payload": {
    "nodeId": "node_1",
    "accepted": true,
    "desiredRevision": 12,
    "heartbeatIntervalMs": 3000,
    "configEndpoint": "/api/v1/node"
  }
}
```

同 SN/MAC 命中墓碑时返回 `TOMBSTONE_ACTIVE`，节点进入退役待处理状态。

### 2.3 心跳

```json
{
  "type": "node.heartbeat",
  "payload": {
    "nodeId": "node_1",
    "uptimeSec": 3600,
    "role": "output",
    "appliedRevision": 12,
    "media": {
      "rxSessions": 4,
      "decoding": 4,
      "layers": 3,
      "streamsLost": 0,
      "decodeErrors": 0
    },
    "ptp": {"state": "synced", "offsetUs": 120},
    "resources": {"cpu": 42, "memMb": 2100, "tempC": 58},
    "firmware": "1.0.0"
  }
}
```

平台连续 3 次未收到判离线。

### 2.4 准备

```json
{
  "type": "media.prepare",
  "payload": {
    "operationId": "op_01H...",
    "wallId": "wall_1",
    "revision": 42,
    "expiresAtTaiNs": 1700000005000000000,
    "sources": [
      {
        "signalId": "in01-hdmi1",
        "mcastIp": "239.10.1.1",
        "port": 20000,
        "sourceIp": "192.168.20.11",
        "codec": "h264",
        "width": 1920,
        "height": 1080,
        "fps": 60
      }
    ],
    "layout": {
      "canvas": {"w": 3840, "h": 2160},
      "planes": [
        {
          "windowId": "w1",
          "signalId": "in01-hdmi1",
          "dst": {"x": 0, "y": 0, "w": 1920, "h": 1080},
          "src": {"x": 0, "y": 0, "w": 1920, "h": 1080},
          "z": 10,
          "visible": true,
          "muted": false
        }
      ],
      "audioOwner": "w1",
      "volume": 80,
      "baseImage": {"revision": 7, "url": "https://.../base.png"}
    }
  }
}
```

回执：

```json
{
  "type": "media.prepare.result",
  "payload": {
    "operationId": "op_01H...",
    "revision": 42,
    "status": "ready",
    "clock": {"offsetUs": 120, "synced": true},
    "sources": [
      {"signalId": "in01-hdmi1", "decoded": true, "firstFrameAtTaiNs": 1700000000100000000}
    ],
    "estimatedCommitMs": 8
  }
}
```

失败时 `status` 为 `blocked`，附 `reason` 和 `failedSources`。

### 2.5 提交

```json
{
  "type": "media.commit",
  "payload": {
    "operationId": "op_01H...",
    "revision": 42,
    "applyAtTaiNs": 1700000000123000000,
    "frameIndex": 738,
    "fps": 60,
    "epochTaiNs": 1700000000000000000,
    "layoutHash": "sha256:..."
  }
}
```

回执：

```json
{
  "type": "media.commit.result",
  "payload": {
    "operationId": "op_01H...",
    "revision": 42,
    "status": "applied",
    "frameIndex": 738,
    "appliedAtTaiNs": 1700000000123010000,
    "layoutHash": "sha256:..."
  }
}
```

失败时 `status` 为 `late`、`failed` 或 `stale`，附 `reason`。

### 2.6 中止与回滚

```json
{"type": "media.abort", "payload": {"operationId": "op_01H...", "reason": "user_cancelled"}}
{"type": "media.rollback", "payload": {"operationId": "op_01H...", "targetRevision": 41}}
```

回滚使用新 operation，节点保留旧布局影子副本。

### 2.7 事件

节点主动上报：

```text
media.stream_lost / media.stream_recovered
media.decode_error / media.decode_recovered
media.layout_applied / media.layout_failed
clock.unsynced / clock.synced
playback.started / playback.ended
```

## 3. 节点本机接口

沿用 `05-tech-links/apis.md` 第 7 节，新增媒体状态：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/v1/node/media/status | 收发会话、解码、图层、音频、PTP |
| GET | /api/v1/node/media/sources | 当前订阅的信号和状态 |
| POST | /api/v1/node/media/restart | 重启媒体引擎（运维） |
| GET | /api/v1/node/media/logs | 最近媒体日志摘要 |
| GET | /api/v1/node/capability | 完整能力报告 |

本机页只展示，不提供跨节点操作。

## 4. 错误码补充

在现有错误码基础上增加媒体相关：

| 错误码 | HTTP/事件 | 含义 |
| --- | --- | --- |
| `MEDIA_SESSION_FAILED` | 503 | 组播加入或会话创建失败 |
| `DECODE_NOT_READY` | 422 | 目标信号尚未解出首帧 |
| `UNSUPPORTED_CODEC` | 422 | 节点不支持该编码 |
| `CLOCK_UNSYNCED` | 409 | PTP 未同步或偏差超阈值 |
| `APPLY_AT_TOO_SOON` | 409 | 保护带不足，拒绝提交 |
| `FRAME_DEADLINE_MISSED` | 409 | 节点错过目标帧 |
| `LAYOUT_CONFLICT` | 409 | 布局片段与绑定不一致 |
| `CAPABILITY_EXCEEDED` | 422 | 解码路数或图层数超限 |
| `ROLLBACK_FAILED` | 500 | 回滚失败，需要人工介入 |

## 5. 版本与兼容

| 版本 | 范围 | 策略 |
| --- | --- | --- |
| `protocolVersion` | 平台与节点消息 | 主版本不兼容，次版本向后兼容 |
| `capabilityVersion` | 能力结构 | 平台按版本解析，未知字段忽略 |
| `snapshotVersion` | 场景快照 | 平台迁移，节点只接收当前版本 |
| `firmware` | 节点固件 | 平台按版本决定可用能力 |

节点注册时上报协议版本，平台拒绝低于最低支持版本的节点，并提示升级。

## 6. 安全

- 平台与节点使用 mTLS，节点证书绑定 SN。
- 消息带 `messageId` 和时间戳，平台拒绝过期消息，防止重放。
- 节点本机 API 使用会话令牌，密码哈希存储，登录限速。
- 组播 SSM 限制源地址，媒体 VLAN 隔离。
- 固件包签名，升级前校验。
- 审计事件不可修改，保留 180 天。

## 7. 与现有文档的差异

| 项 | 现有草案 | 本文建议 |
| --- | --- | --- |
| 窗口坐标 | 未定义坐标系 | 增加整墙像素坐标和格位矩阵 |
| 白名单 | 只有传输方式 | 增加组播地址、端口、编码参数 |
| operation | 有状态和时间 | 增加 apply_at、frame_index、layout_hash |
| 节点能力 | 字段分散在 dvs_node | 独立能力结构，版本化 |
| 播放任务 | 有八态 | 增加 operation_id 和 target_node_id |
| 审计 | 通用事件 | 增加媒体和时钟事件类型 |

这些差异在开发评审后回写 `05-tech-links/` 和对应 REQ 的 `links.yaml`。

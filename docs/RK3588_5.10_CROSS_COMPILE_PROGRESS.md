# RK3588 5.10 Debian 交叉编译 — 进度总览

> 本文件是 `app/rk3588_end2end` 与 `app/rk3588_mp4_dist` 在 RK3588 Debian 5.10 上交叉编译工作的**进度快照**。
> 详细操作指南见 `docs/dev/compile/5.10-debian-cross-compile.md`；板端内核能力见 `docs/env/RK3588_5.10_AF_XDP_EBPF.md`。

## 1. 目标

把两个 rk3588 app 在 x86_64 上交叉编译成 aarch64，部署到 RK3588 Debian 11（内核 5.10.226）板运行。走 **native AF_XDP** 后端（板端 5.10 内核已具备 XDP/BPF/BTF/大页，见 AF_XDP 文档）。

## 2. 环境拓扑

| 角色 | 主机 | OS | 用途 |
|---|---|---|---|
| 本地 | WSL | Arch | 前期探测、文档、scp 中转 |
| 编译服务器 | `devs`（`ssh devs`） | Ubuntu 18.04 x86_64，`/data/kkkqkx` | **实际交叉编译** |
| 目标板 | `board`（`ssh board`，root） | Debian 11 (bullseye)，内核 5.10.226 | 运行产物、装运行库 |

## 3. 两个 app 的依赖（交叉编译视角）

见指南 §1。要点：
- **end2end (`e2e_app`)**：`libdrm`(必需) + `threads` + `rockchip_mpp`/`librga`/`mtl`/`json-c`（缺则 `e2e_app` 静默跳过 → 必须做产物断言）。
- **mp4_dist (`mp4_dist_tx`/`mp4_dist_rx`)**：`mtl`(必需) + FFmpeg(`libavformat/avcodec/avutil`) + `json-c` + RX 侧 `rockchip_mpp`/`libdrm`/`alsa`。
- `mtl`/`libdpdk` 不在板上，由交叉构建产生后进 `$STAGING`，经 `PKG_CONFIG_PATH` 暴露。
- 板端系统库已随 `sysroot/` 提供（libdrm / FFmpeg-4.4 / rockchip_mpp 1.3.9 / librga 2.1.0 / alsa / json-c / pcap / openssl / zlib）。

## 5. 工具链结论（关键，已纠偏）

**现象（本地 Arch）**：`aarch64-linux-gnu-gcc 16.1.0` 下 `--sysroot` 不生效（系统头目录硬编码绝对路径 `/usr/aarch64-linux-gnu/include`，无法 relocate 到 Debian 布局 sysroot）。

**根因**：Arch cross gcc 非 Debian 多 arch 感知；Debian/Ubuntu 的 `gcc-aarch64-linux-gnu` 才是。

**重大纠偏（已验证）**：devs 上**不能**用 RK3588 SDK 自带的 `aarch64-linux-gnu-gcc-12`——它实为本机 **aarch64 原生二进制**（ELF ARM aarch64，解释器 `/lib/ld-linux-aarch64.so.1`），在 x86 的 devs 上根本跑不起来。devs 也没有任何 x86 宿主的 aarch64 交叉 gcc；Ubuntu 18.04 apt 只有 gcc-7.4/gcc-8.4（太旧，跑不动 DPDK 26.07）。qemu 路径也跑不通（qemu 18.04 太旧，无法运行 bookworm/glibc2.36 的 chroot gcc）。

**采用方案**：在**工作站用本地代理**（`http_proxy=http://localhost:7890`）下载 ARM 官方 x86 宿主交叉编译器 **`aarch64-none-linux-gnu-gcc` 13.3.rel1**（约 150MB；直连 developer.arm.com / github 均被限速或阻断，须走代理抓 `armkeil.blob.core.windows.net` 的包再 rsync 到 devs），然后在 devs 解压使用。该 toolchain 自带 gcc/crt/libgcc，配合板端 sysroot 用 `--sysroot` 精确匹配板子 glibc 2.31（交叉文件 §6.1 额外加 `-isystem .../aarch64-linux-gnu` 与 `-B .../aarch64-linux-gnu` 找 arch 专属头与 crt）。meson/ninja 优先用 SDK buildroot host 版，过旧则 `pip3 install meson ninja`。

## 7. 已知风险 / 偏差

- **FFmpeg 4.4 vs 7.0**：板端发行版是 4.4（`libavformat 58.45.100`），`versions.env` 钉 7.0。接受发行版版本先跑通；要严对齐则按文档 02 §4.4 交叉自编 7.0。
- **DPDK 26.07 需要较新编译器**：用 ARM GNU Toolchain 13.3（gcc-13）满足；buildroot 的 meson 若过旧需升级（或 `pip3 install meson ninja`）。
- **yt6801 仅 generic XDP + copy**：零拷贝不可得；pacing 走 TSC 软件 pacing。
- **无 HW PTP / `/dev/ptp*`**：mp4_dist 的 PTP 方案需软件时间戳或系统时钟。
- **`CONFIG_KPROBES` 未开**：`tools/ebpf/` fentry/kprobe 不可用（BTF 在，CO-RE 可用）。
- 其余见指南 §10 风险表（RB11/RB12/RB13/RB16/RB18）。
